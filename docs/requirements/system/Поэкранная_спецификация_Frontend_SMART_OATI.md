# Поэкранная frontend-спецификация и UX
## «Диаграмма Ганта — проект SMART OATI»

**Версия документа:** 1.0  
**Дата:** 2026-10-28  
**Соответствует системной постановке Frontend:** версия 1.0  
**Соответствует OpenAPI:** версия 1.2  
**Соответствует API Gateway:** версия 1.2

---

## 1. Общие правила

- Desktop-first.
- Основной диапазон: 1280–2560 px.
- Минимальная ширина: 1024 px.
- Мобильная адаптация — отдельный этап.
- Язык интерфейса — русский.
- SSR для auth, projects, audit, notifications, admin.
- Gantt — client-only.
- API — только через API Gateway.
- Sync WebSocket и Notification WebSocket — отдельно.
- Ошибки API — RFC 7807.
- Все опасные действия — с подтверждением.
- Кнопки недоступных действий скрываются по роли.
- Серверная проверка прав обязательна.

## 3. Вход

### 3.1. Макет

- split-screen на desktop;
- слева название продукта и краткое описание;
- справа центрированная форма.

### 3.2. Поля

- email*;
- пароль*;
- «Запомнить меня»;
- «Показать пароль»;
- «Забыли пароль?»;
- «Войти»;
- «Зарегистрироваться».

### 3.3. Поведение

- после входа — `/projects` или исходный защищённый маршрут;
- restore по remember-cookie выполняется автоматически;
- при `423` — сообщение о блокировке;
- при неподтвержденном email — сообщение и повторная отправка;
- при `401` — общая ошибка без раскрытия существования email;
- при `429` — `Retry-After`.

### 3.4. Состояния

- loading;
- disabled-кнопка;
- inline-ошибки;
- ошибка формы;
- успешный вход.

## 4. Регистрация

### 4.1. Поля

- email*;
- фамилия*;
- имя*;
- отчество;
- пароль*;
- подтверждение пароля*;
- чекбокс согласия с правилами/политикой*;
- timezone/locale определяются автоматически;
- кнопка «Зарегистрироваться».

### 4.2. Поведение

- проверка формата email;
- пароль по `system_settings`;
- пароль и подтверждение должны совпадать;
- после регистрации — экран ожидания подтверждения;
- автоматический вход не выполняется.

### 4.3. Состояния

- ошибки полей;
- email уже занят;
- `429`;
- успех.

## 5. Подтверждение email

Три состояния:

1. Проверка токена.
2. Успех — кнопка «Войти».
3. Ошибка/истёк токен — «Отправить письмо повторно».

Автоматический вход не выполняется.

- кнопка «Сохранить»;

### 9.2. Layout

- закреплённая колонка наименований;
- изменяемая ширина;
- перенос названий;
- временная шкала;
- прокрутка только диаграммы;
- полосы сверху и снизу;
- зум только шкалы;
- сохранение центральной даты.

### 9.3. Строки

- направление;
- задача;
- подзадача;

- drag/resize;
- статус, прогресс, приоритет, ответственный;

### 9.4. Контекстное меню

- добавить комментарий;
- свернуть/развернуть;
- удалить.

- открытая модалка не закрывается;
- конфликт — отдельная модалка;
- `snapshot_required` — перезагрузка;
- индикатор `Синхронизировано/Сохраняется/Ошибка/Нет связи`.

### 9.6. Импорт

- баннер «Импорт выполняется»;
- блокировка изменений;
- статус;
- отчёт после завершения.

### 9.7. PDF/печать

- текущий клиентский механизм;
- фильтры, зум и сворачивание учитываются.

## 20. Критерии приемки

1. Все маршруты реализованы.
2. Auth-экраны соответствуют сценариям.
3. Регистрация содержит три поля ФИО и consent.
4. Проекты имеют вкладки active/archive/deleted.
5. Удаленные проекты только в отдельной вкладке.
6. Создание проекта администратором позволяет выбрать владельца.
7. Гант сохраняет функциональность версии 9.
8. Карточки направления/задачи используют явное сохранение.
9. Назначения поддерживают до двух соисполнителей.
10. Зависимости редактируются только на диаграмме.
11. Комментарии работают в боковой панели.
12. Исполнители доступны только админу/владельцу.
13. ФИО исполнителя — три поля.
14. Участники видят список, управляют админ/владелец.
15. Приглашения показывают pending и expired.
16. Уведомления работают через отдельный WebSocket.
17. Настройки уведомлений автосохраняются.
18. Аудит имеет общий/privileged/project views.
19. Админка управляет пользователями, ролями и настройками.
20. Последний администратор защищен.
21. Профиль управляет сессиями и Telegram.
22. Служебные страницы и баннеры работают.
23. Печать отделена от интерфейса.
24. Базовые keyboard-правила соблюдены.
