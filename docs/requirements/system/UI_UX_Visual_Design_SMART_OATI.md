## 1. Назначение

Документ фиксирует визуальное направление SMART OATI и то, что уже подготовлено для перехода к полноценному дизайну:

- дизайн-токены;
- HTML/CSS-прототип ключевых экранов;
- UI kit;
- скриншоты;
- визуальные спецификации;
- рекомендации по Figma, accessibility, адаптивности и внедрению.

Это не замена Figma-макетам и не финальный pixel-perfect design. Прототип нужен, чтобы согласовать направление, плотность интерфейса, иерархию и поведение до разработки полноценной дизайн-системы.

## 3. Визуальная концепция

### 3.1. Характер

- Спокойный, плотный, рабочий интерфейс.
- Ощущение надежной корпоративной системы, а не развлекательного продукта.
- Главный акцент — данные, сроки, зависимости и действия.
- Синий primary ассоциируется с управлением, точностью и технологичностью.
- Теплые статусы используются точечно, чтобы не превращать таблицы в «светофор».

### 3.2. Принципы

1. **Данные важнее декора.** Никаких иллюстраций и градиентов внутри рабочих таблиц.
2. **Один primary-акцент.** Синий цвет ведет к главному действию; статусы используют семантические оттенки.
3. **Плотность с воздухом.** Компактные строки, но четкие группы и отступы между смысловыми блоками.
4. **Цвет не единственный носитель смысла.** Статусы всегда имеют текст и/или иконку.
5. **Предсказуемость.** Одинаковые паттерны для проектов, диаграмм, аудита и админки.
6. **Сначала desktop.** Основной сценарий — 1440–1920 px; мобильная версия — отдельный этап.

### 3.3. Чего избегать

- Пестрых акцентных цветов без семантики.
- Тяжелых теней и glassmorphism в рабочих областях.
- Мелкого текста ниже 11 px для значимой информации.
- Иконок без текстовой подписи в критичных действиях.
- Анимации, мешающей быстрой работе с таблицами и Гантом.

## 5. Компоненты

### 5.1. App header

- Высота 64 px, белый фон, нижняя граница.
- Слева — brand mark + SMART OATI.
- Навигация: Проекты, Исполнители, Аудит, Админка.
- Справа — уведомления и user chip.
- Активный раздел: темный текст + синяя линия 2 px.
- На узких desktop-экранах навигация может сжиматься, но не превращается в burger в первой версии.

### 5.2. Кнопки

- **Primary:** одно главное действие на экран/секцию.
- **Secondary:** альтернативные действия, фильтры, экспорт.
- **Ghost:** отмена, вторичные действия в toolbar.
- **Danger:** удаление и необратимые действия, только с подтверждением.
- **Icon button:** только для знакомых иконок; обязателен `aria-label`.
- Минимальная высота 36 px; для критичных действий на touch-устройствах — 44 px.

### 5.3. Поля и формы

- Label над полем, 12 px.
- Подсказка под полем, 11–12 px.
- Ошибка: красная граница, красный текст, не только цвет — текст ошибки обязателен.
- Фокус: видимое кольцо; в production усилить до контрастного 2 px + offset.
- Пароль: кнопка показать/скрыть, Caps Lock warning.
- ФИО: три отдельных поля — фамилия, имя, отчество.

### 5.4. Таблицы

- Заголовок uppercase, 10–11 px, muted.
- Строка 52–56 px, hover soft-blue.
- Действия — в конце строки, `more`/chevron.
- Числовые и временные значения — выравнивать предсказуемо.
- На 1024–1280 px допустим горизонтальный scroll, но ключевые колонки должны оставаться видимыми.
- Для audit — фиксированная ширина колонок и detail drawer.

### 5.5. Badges и статусы

- Soft-фон + насыщенный текст.
- Статус всегда содержит текст.
- Точка перед текстом используется для статусов, но не заменяет текст.
- Критический путь в Ганте: темный контур + подпись/легенда.
- Приоритеты: critical/high/medium/low; не смешивать со статусами.

### 5.6. Гант

- Левая колонка: WBS, название, статус, прогресс.
- Правая: временная шкала, месяцы, недели, today line.
- Строки direction/task/subtask различаются жирностью и отступом.
- Прогресс показывается заливкой и числом.
- Заблокированные задачи — красная soft-заливка.
- Критический путь — контур.
- Сегодняшняя дата — вертикальная линия + label.
- Drawer комментариев — 360 px, не перекрывает рабочую область на широком экране; на 1440 контент сжимается.
- Для accessibility нужен альтернативный табличный режим.

### 5.7. Drawer

- Используется для комментариев и деталей аудита.
- Заголовок + подпись + close.
- Скроллится только body.
- Composer фиксирован внизу.
- При открытии: focus trap, `Escape` закрывает, focus возвращается на триггер.
- Для destructive/detail действий — явные кнопки, не только иконки.

### 5.8. Modal

- Ширина 520–680 px.
- Заголовок, описание, body, footer.
- Одно primary-действие.
- Закрытие по `Escape` и клику по overlay.
- Не использовать для длинных форм; длинные формы — отдельная страница/панель.

### 5.9. Toast / Alert / Empty state

- Toast: успех/нейтральное подтверждение, auto-dismiss 4–6 с, не для ошибок, требующих решения.
- Alert: ошибка/предупреждение, остается до действия пользователя.
- Empty state: иконка, короткий заголовок, объяснение, одно действие.
- Skeleton — для первичной загрузки таблиц и Ганта; не показывать бесконечный spinner.

## 6. Экраны

### 6.1. Auth

**Цель:** быстрый вход и понятная регистрация.

- Split-screen: слева brand-панель, справа форма.
- Слева: логотип, ценностное сообщение, 3 преимущества.
- Справа: email, пароль, «Запомнить меня», «Забыли пароль?», primary «Войти».
- Ниже: регистрация.
- Ошибки — над формой или под полем; не раскрывать, существует ли email.
- Loading — disabled submit + spinner.
- CAPTCHA/lockout — только после нескольких неудач, с понятным сообщением.
- На 1024 px split-screen можно сохранить; на меньших ширинах — одна колонка.

### 6.2. Проекты

**Цель:** быстро найти проект и понять свою роль.

- Page head: eyebrow, title, subtitle, фильтр, create.
- Tabs: Активные / Архив / Удаленные с counts.
- Таблица: проект, роль, диаграммы, владелец, обновлен, действия.
- Роль — badge; владелец — avatar + имя.
- Пустое состояние: «Проектов пока нет» + create.
- Удаленные: явная пометка, restore только для admin/owner.
- Архив: read-only по умолчанию.
- Поиск и фильтры сохраняются в query string.

### 6.3. Гант

**Цель:** увидеть план, зависимости, прогресс и проблемы.

- Breadcrumbs: Проекты / Проект / Диаграмма.
- Title + status + revision + updated + participants.
- Sync state: «Синхронизировано» / «Синхронизация...» / «Офлайн».
- Toolbar: направление, фильтры, связь, рабочие дни, импорт/экспорт, PDF, zoom.
- Слева — структура работ; справа — timeline.
- Комментарии — drawer.
- Карточка задачи открывается по клику; сохранение явное.
- Изменения приходят по WebSocket; конфликт — понятный banner.
- Для печати — отдельный print layout без drawer/toolbar.

### 6.4. Уведомления

**Цель:** быстро понять, что требует внимания.

- Tabs: Все / Непрочитанные.
- Список: иконка типа, заголовок, проект/объект, время, действие.
- Непрочитанное — не только точка, но и фон/метка.
- Действия: открыть объект, отметить прочитанным.
- Массовое «Отметить все прочитанными».
- Пустое состояние: «Новых уведомлений нет».
- Настройки уведомлений — отдельная страница/панель.

### 6.5. Аудит

**Цель:** расследовать изменения и действия пользователей.

- Filters: период, проект, действие, важность.
- Таблица: время, пользователь, действие, объект, важность, детали.
- Detail drawer: пользователь, действие, объект, проект, IP, request ID, correlation ID, diff.
- Privileged-события — отдельный фильтр/журнал.
- Export отсутствует по требованиям.
- Не показывать лишние персональные данные.
- Для diff — monospace, прокрутка, copy.

### 6.6. Админка

**Цель:** управлять пользователями и системными настройками.

- Settings nav: Пользователи, Системные настройки, Журнал администраторов.
- Users table: пользователь, статус, глобальные роли, последний вход, действия.
- Создание/редактирование — modal или отдельная страница.
- Блокировка/разблокировка — подтверждение.
- Роли: `app_admin`, `auditor`, без глобальных ролей.
- Опасные действия — danger + audit.
- Системные настройки — группы, явное сохранение, validation.

## 7. Состояния

Для каждого экрана и компонента предусмотреть:

| Состояние | Требование |
|---|---|
| Loading | Skeleton для контента, spinner только для коротких действий |
| Empty | Иконка, объяснение, одно действие |
| Error | Что произошло, что делать, retry; не терять введенные данные |
| No access | Понятное объяснение и путь к запросу доступа |
| Offline | Banner, очередь изменений, статус синхронизации |
| Conflict | Показать конфликт, предложить обновить/сохранить копию |
| Unsaved | Индикатор, подтверждение при уходе |
| Destructive | Confirmation с названием объекта |
| Success | Toast + обновление данных без полной перезагрузки |
| Long content | Truncation + tooltip/expand, не ломать layout |
| Large lists | Пагинация/виртуализация, сохранение фильтров |

## 8. Accessibility

Цель: WCAG 2.1 AA для ключевых сценариев.

### Обязательно

- Контраст текста ≥ 4.5:1; крупного ≥ 3:1.
- Не использовать `#94A3B8` для значимого текста на белом.
- Все интерактивные элементы доступны с клавиатуры.
- Видимый focus ring; не полагаться только на `outline: none`.
- Иконки-кнопки имеют `aria-label`.
- Статусы не передаются только цветом.
- Формы: label, `aria-describedby` для ошибок, `aria-invalid`.
- Drawer/modal: focus trap, `Escape`, возврат фокуса.
- Таблицы: корректные `th`, caption/aria-label, сортировка озвучивается.
- Гант: альтернативный табличный режим и текстовая легенда.
- Анимации: `prefers-reduced-motion`.
- Минимальная зона нажатия: 36 px desktop, 44 px touch.

### Известные ограничения прототипа

- Много текста 10–11 px.
- `--color-text-subtle` не проходит AA на белом.
- Focus ring с alpha 0.22 может быть недостаточно контрастным.
- Не реализованы реальные keyboard-сценарии, ARIA и focus trap.
- Нет мобильной и touch-версии.
- Нет dark theme.

Эти пункты нужно закрыть в production-дизайне и frontend-реализации.

## 9. Адаптивность

| Диапазон | Поведение |
|---|---|
| 1024–1279 | Компактный desktop: уменьшить padding, toolbar wrap, таблицы со scroll |
| 1280–1439 | Основной компактный режим; drawer сжимает контент |
| 1440–1799 | Референсный режим; полный toolbar, drawer 360 |
| 1800–2559 | Контент max-width, больше воздуха; drawer не перекрывает контент |
| 2560+ | Ограничить рабочую область; не растягивать таблицы на всю ширину |
| < 1024 | Вне первой версии; отдельный mobile UX |

Рекомендация: не делать «резиновый» Гант на мобильном. Для мобильного нужен отдельный режим: список задач + детали, без горизонтальной временной шкалы.

---

## 10. Motion

- Длительность: 120–180 ms для hover/focus, 180–240 ms для drawer/modal.
- Easing: ease-out.
- Не анимировать большие таблицы и Гант при каждом обновлении.
- Sync/status — мягкий fade, не пульсация.
- Уважать `prefers-reduced-motion`.
- Drawer: slide + fade overlay; modal: scale 0.98 → 1.

---

## 11. Контент и микрокопирайтинг

- Русский язык, sentence case.
- Короткие глагольные кнопки: «Создать проект», «Сохранить», «Отправить».
- Статусы: «В работе», «Выполнено», «Заблокировано», «Запланировано».
- Ошибки: что произошло + что делать.
- Не использовать технические коды в основном тексте; коды — в audit/detail.
- Даты: `28.10.2026`, время `10:42`; относительные — только как дополнение.
- Не сокращать названия проектов без необходимости.
- Для destructive: «Удалить проект? Действие можно отменить в течение 30 дней» — если restore предусмотрен.

## 12. Бренд, иконки, иллюстрации

- Brand mark: абстрактная диаграмма/столбцы в квадрате.
- Primary gradient допустим только в brand-зоне Auth; в рабочих экранах — плоский цвет.
- Иконки: Lucide/inline SVG, stroke 1.8, размер 16/20/24.
- Не использовать emoji в интерфейсе.
- Иллюстрации — только для empty/onboarding; в рабочих таблицах не нужны.
- Для темной темы нужен отдельный набор токенов; в первой версии не требуется.

### Figma variables

- Color: background, surface, text, border, primary, success, warning, danger, status.
- Typography: display, h1–h3, body, caption, mono.
- Spacing: 4-based scale.
- Radius: 4/6/8/12/16/pill.
- Modes: `Desktop 1440`, `Desktop 1024`, eventual `Dark`.

### Components и variants

- Button: primary/secondary/ghost/danger, sm/md/lg, default/hover/focus/disabled/loading.
- Input: default/focus/error/disabled/readonly.
- Badge: status/priority/role, with/without dot.
- Table row: default/hover/selected/disabled.
- Gantt bar: done/progress/blocked/planned/critical/selected/dragging.
- Drawer: comments/audit details; open/closed/loading/error.
- Modal: create/edit/delete/confirm; sizes.
- Toast/Alert: success/error/warning/info.

### Обязательные frames

- 1440×1024 для каждого экрана.
- 1024×768 для проверки плотности.
- 1920×1080 для широкого desktop.
- Gantt: drawer closed/open, long labels, 50+ rows, empty, loading, error.
- Таблицы: empty, loading, error, no access, pagination, long text.
- Auth: default, error, loading, lockout, registration.

## 14. Маппинг на frontend

- Nuxt 3 SSR, Vue 3, JavaScript без TypeScript.
- Tailwind CSS 4: перенести токены в `@theme`/CSS variables; не хардкодить hex в компонентах.
- `tokens.css` — источник истины для CSS variables.
- `prototype.css` — референс, не production-стиль; компоненты переписать на Tailwind/собственные Vue-компоненты.
- Иконки — inline SVG/Lucide, не icon font.
- Все размеры и состояния должны быть в токенах/классах, не в inline styles.
- Для Ганта — отдельный компонент с виртуализацией и альтернативным table view.
- Для drawer/modal — focus trap и управление фокусом на уровне composable.
- Для тем/плотности — CSS variables + data-атрибуты, без дублирования компонентов.

## 15. Design QA checklist

- [ ] Все экраны собраны на 1440 и 1024.
- [ ] Нет текста ниже 11 px для значимой информации.
- [ ] Все статусы имеют текст, не только цвет.
- [ ] Контраст проверен для текста, границ, focus ring.
- [ ] Все interactive-элементы имеют hover/focus/disabled/loading.
- [ ] Формы: label, hint, error, aria.
- [ ] Таблицы: empty/loading/error/no access/pagination.
- [ ] Гант: критические, заблокированные, пустые, длинные названия.
- [ ] Drawer/modal: Escape, focus trap, возврат фокуса.
- [ ] Destructive-действия имеют подтверждение.
- [ ] Ошибки не теряют введенные данные.
- [ ] Даты/время/статусы консистентны.
- [ ] Нет горизонтального overflow на 1024.
- [ ] Проверены zoom 200% и reduced motion.
- [ ] Все иконки-кнопки имеют aria-label.
- [ ] Скриншоты и макеты обновлены.

## 16. Ограничения текущего пакета

- Прототип статический; реальные API, WebSocket и права не подключены.
- Нет pixel-perfect Figma-макетов.
- Нет мобильной версии.
- Нет dark theme.
- Нет финального бренд-гайда, логотипа и иллюстраций.
- Нет UX-исследований и проверки на реальных пользователях.
- Скриншоты сделаны в Chrome headless; шрифты могут отличаться от целевой машины.
- Некоторые состояния (loading/error/offline) описаны, но не показаны в прототипе.
