# Системная постановка: веб-приложение «Диаграмма Ганта — проект SMART OATI»

Документ описывает приложение **полностью и самодостаточно**: по нему приложение можно воссоздать с нуля без доступа к исходному коду.

> **Статус:** историческая спецификация локального однофайлового приложения на HTML/localStorage. Она не описывает текущий серверный RP Gant и не должна использоваться как контракт `apps/frontend`; актуальный статус — в [`docs/IMPLEMENTATION-STATUS.md`](../../IMPLEMENTATION-STATUS.md), серверные API — в `openapi/` и `proto/`.

> **Версия 9.** При наведении на связь подсвечиваются обе задачи, которые она соединяет, и сама линия (6.20, 6.31.2). Ранее (Версия 8) — сворачивание задач с подзадачами и авто-окончание по подзадачам (6.5, 6.11); (Версия 7) — интерактивные связи и их стиль (6.31); (Версия 6) — ручная ширина колонки и перенос названий (6.1, 6.3); (Версия 5) — закреплённая колонка и зум только таймлайна (6.1, 6.24); (Версия 4) — название диаграммы (6.30); (Версия 3) — авто-статус направления и фильтрация (6.29). Внесены правки по итогам сверки постановки и реализации: устранены противоречия, недоспецифицированность и зафиксированы решения по спорным местам (помечены `[уточнено]`). Полный список правок — в конце документа (changelog).

## 1. Сводка

**Что это.** Самодостаточный HTML-файл (один файл, без сборки, без сервера), отображающий план проекта в виде диаграммы Ганта с интерактивным редактированием: статусы, проценты, владельцы, Jira, названия, описания, комментарии, даты, порядок направлений, добавление и удаление задач, перетаскивание баров, режим рабочих дней, граф зависимостей, критический путь, учёт досрочного выполнения, **каталог исполнителей** (выбор ответственного/исполнителя/соисполнителя из списка при создании и редактировании), **авто-статус направления** по готовности подзадач, **фильтры по статусу и ответственному** в шапке (6.29), **название диаграммы** (6.30), **закреплённая колонка названий** с масштабированием/прокруткой только таймлайна (6.1, 6.24), **ручная ширина колонки** с переносом длинных наименований (6.1), **интерактивное редактирование связей** с настройкой их вида (6.31), **сворачивание задач с подзадачами** и **авто-окончание задачи по подзадачам** (6.5, 6.11), а также **подсветка связанных задач при наведении на связь** (6.20).

**Ключевые принципы:**

| # | Принцип |
|---|---------|
| 1 | **Один файл**. Вся разметка, стили и логика в одном `.html`. Единственные внешние зависимости — CDN-библиотеки для PDF (html2canvas, jsPDF); при их отсутствии — fallback на системную печать. |
| 2 | **План не зашит в файл.** Приложение не содержит предустановленных данных. При первом открытии (пустой localStorage) показывается **пустой план**, который пользователь наполняет вручную или импортом (JSON/CSV). |
| 3 | **Весь план живёт в браузере** (localStorage) и редактируется **«на месте»**: любое изменение (задача, статус, даты, флаги, порядок) сразу записывается в саму запись плана. Ничего не пишется на сервер и не покидает браузер. |
| 4 | **Экспорт/импорт JSON и CSV** — способ переноса плана между браузерами и резервное копирование. Импорт заменяет текущий план. Кнопка «Новая диаграмма» полностью очищает план до пустого (см. 6.23); это единственное действие очистки, а пустой план — стартовое состояние. |
| 5 | **Чистая ванильная JS** (ES2020), DOM через `document.createElement` + `innerHTML`-шаблоны. Никаких фреймворков и бандлеров. |

## 2. Техническая платформа и ограничения

- **Среда выполнения:** современный браузер (Chrome/Edge/Firefox); требуется поддержка localStorage, `Date`, `FileReader`, `Blob`, `URL.createObjectURL`, CSS flexbox/grid.
- **Сборка:** отсутствует. Файл редактируется как есть; для валидации — `node --check` на извлечённом скрипте.
- **Кодировка:** UTF-8; интерфейс — русский.
- **Сеть:** требуется только при генерации PDF (CDN):
  - `https://cdnjs.cloudflare.com/ajax/libs/html2canvas/1.4.1/html2canvas.min.js`
  - `https://cdnjs.cloudflare.com/ajax/libs/jspdf/2.5.1/jspdf.umd.min.js`
  - При недоступности — `window.print()` с подсказкой выбрать альбомную ориентацию и «Сохранить как PDF».
- **Печать:** в файле есть print-стили (`@page { size: A4 landscape }`), чтобы системная печать выглядела корректно.
- **Ограничение размера импорта:** 5 МБ.

## 3. Модель данных

### 3.1. Запись плана

Каждый элемент плана — объект:

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | string | WBS-идентификатор: `1`, `1.1`, `1.1.1` |
| `parent` | string\|null | ID родителя (`null` для направлений) |
| `lvl` | number | 1 — направление, 2 — задача, 3 — подзадача |
| `type` | string | «Направление» / «Задача» / «Подзадача» |
| `task` | string | Наименование |
| `result` | string\|null | Результат / критерий готовности |
| `desc` | string\|null | Описание задачи или направления (необязательное, 6.25) |
| `comments` | array\|null | Комментарии: `[{id, text, author, createdAt, updatedAt}]` (6.26) |
| `doneDate` | string\|null | Фактическая дата завершения, `ГГГГ-ММ-ДД` (6.27); **у направлений (lvl1) всегда `null`** |
| `ownerId` | string\|null | Ответственный: **id исполнителя из каталога** (6.28); `null` — не назначен |
| `execId` | string\|null | Исполнитель: id исполнителя из каталога (6.28); `null` — не назначен |
| `coId` | string\|null | Соисполнитель: id исполнителя из каталога (6.28); `null` — не назначен |
| `start` | string | Дата начала, `ГГГГ-ММ-ДД` |
| `end` | string | Дата окончания, `ГГГГ-ММ-ДД` |
| `days` | number | Календарная длительность = (end − start) в днях + 1 |
| `status` | string\|null | «Запланировано», «В работе», «Выполнено», «Заблокировано»; **у направлений (lvl1) хранится всегда `null`** (расчётный статус — §5, 6.29) |
| `pct` | number\|null | Процент выполнения 0–100; **у направлений (lvl1) хранится всегда `null`** (расчётный процент — §5, 6.29) |
| `prio` | string | «Критический», «Высокий», «Средний», «Низкий» |
| `deps` | string\|null | Зависимости: ID задач через `"; "` |
| `jira` | string\|null | Номер задачи в Jira (например, `OATI-123`) |

**Инвариант уровней `[уточнено]`:** для любой записи с `lvl === 1` **хранимые** поля `status`, `pct`, `doneDate` **обязаны** быть `null`. Это правило поддерживается всеми путями изменения записи:
- редактирование в модалке (6.10) — для lvl1 поля скрыты и при сохранении принудительно обнуляются;
- перенос по дереву (6.18.1) — при переносе записи на lvl1 поля принудительно обнуляются;
- импорт (6.15, 6.22) — при `level === 1` значения `status`/`pct`/`doneDate` игнорируются с предупреждением.

**`[уточнено, Версия 3]`** Инвариант относится только к **хранимым** полям. Для отображения, тултипа и фильтрации у направления вычисляются **расчётные** `effStatus`/`effPct` по его подзадачам (5, 6.29): когда все подзадачи выполнены, направление показывается как «Выполнено 100%». Расчётные значения не записываются в план и не выгружаются в JSON/CSV (там для lvl1 остаются `null`, 6.14/6.22).

Имена исполнителей **не хранятся** в записи плана: `ownerId`/`execId`/`coId` — это **жёсткие ссылки по id** на записи каталога исполнителей (6.28). Отображаемое ФИО всегда разрешается из каталога (см. `effOwner`/`effExec`/`effCo` в §5); при `null` или при отсутствии id в каталоге выводится плейсхолдер «—». Это исключает дубли и «рассинхрон» имён: переименование исполнителя в каталоге автоматически отражается во всех ссылках.

### 3.2. Правила WBS

- ID строится по уровням: направление — целое число (`1`, `2`, …), задача — `N.M`, подзадача — `N.M.K`.
- Новое направление: `nextTopId()` = `max(числовых ID lvl1) + 1`.
- Новая подчинённая: `nextChildId(parentId)` = `parentId + "." + (max(последних компонент детей) + 1)`.
- ID **стабильны**: порядок строк и перенумерация не меняют ID (ID используются в `deps`, `parent` и экспорте).
- Поддерживается максимум 3 уровня; в UI создание 4-го уровня запрещено (lvl3 в дереве родителей не выборочен).

### 3.3. Стартовое состояние

- В приложении **нет предустановленного плана**. При первом открытии (в localStorage нет ключа `oati_gantt_plan_v1`) план пуст.
- Пустой план отображается пустой таблицей со шкалой (дефолтный диапазон — «сегодня ±30 дней», см. 6.2, 6.23) и строкой-подсказкой.
- Наполнение: кнопка «+ Добавить задачу» (создание вручную), кнопка «＋» в строке (создание подзадачи из строки, 6.8.1) либо импорт JSON/CSV.

### 3.4. Каталог исполнителей и жёсткая ссылка по id

- **Каталог** (`oati_gantt_executors_v1`) — массив `{id, name, role}`:
  - `id` — уникальный инкрементный идентификатор (`ex1`, `ex2`, …); `nextExecutorId()` = max(числовых суффиксов) + 1. ID **стабильны** и используются как ключ жёсткой ссылки из плана.
  - `name` — ФИО, **обязательное**, **уникальное** (сравнение — trim + без учёта регистра). Уникальность обеспечивается на добавлении/переименовании (нарушение — блокирующая ошибка).
  - `role` — должность/роль, необязательная (пустая строка = не задана).
- **Жёсткая ссылка:** в записях плана хранятся только `ownerId`/`execId`/`coId` (id из каталога или `null`). Имя **не дублируется** в плане — всегда разрешается из каталога (`resolvePerson`, §5). Поэтому:
  - переименование исполнителя в каталоге **автоматически** отражается во всех задачах (ссылка по id не ломается);
  - удаление исполнителя из каталога **не трогает** записи плана — их id становится «сиротой»: отображается плейсхолдер «—» и пометка «исполнитель не найден» (6.7, 6.28), запись не удаляется.
- **Миграция с планов в «старом» формате** (записи со строковыми `owner`/`executor`/`coexecutor` и без `ownerId`/`execId`/`coId` — т.ч. все ранее созданные планы и экспорт): при **загрузке** (`loadPlan`) и при **импорте** выполняется нормализация каждой записи:
  - если есть `ownerId`/`execId`/`coId` — они сохраняются (при этом строковые варианты игнорируются);
  - если `ownerId` пуст, а `owner` (строка) заполнен — по строке находится запись каталога с тем же именем (trim, без учёта регистра) либо **создаётся новая** (id = `nextExecutorId()`), после чего `ownerId` = этот id, а строковое поле `owner` **удаляется**; аналогично `executor`→`execId`, `coexecutor`→`coId`;
  - если и id, и строка пусты — `ownerId = null`.
  - Миграция идемпотентна и выполняется **до** первого рендера; после неё в плане хранятся только id.
- **Совместимость экспорта:** JSON-экспорт всегда выгружает каталог (`executors`) и id-ссылки (§7); CSV — имена (разрешённые) + блок каталога после таблицы (6.22). Импорт понимает и «новый» (id), и «старый» (строки) формат (нормализация выше).

## 4. Хранилище (localStorage)

Все ключи с префиксом `oati_gantt_`:

| Ключ | Тип | Назначение |
|------|-----|------------|
| `oati_gantt_plan_v1` | объект `{tasks: [...], meta: {project, source, updatedAt, depStyles}}` | **весь план**: массив записей (§3.1) и метаданные. Единственный источник данных плана. Если ключа нет — план пуст. |
| `oati_gantt_flags_v1` | объект `{ [id]: {bp: bool, sp: bool} }` | флаги «есть БП» / «есть СП» |
| `oati_gantt_collapsed_v1` | массив ID строк с потомками | свёрнутые строки: направления (lvl1) и задачи с подзадачами (lvl2) `[Версия 8]` |
| `oati_gantt_dir_order_v1` | массив ID направлений | явный порядок направлений (если пуст — порядок по WBS) |
| `oati_gantt_workdays_v1` | объект `{mode: "calendar"\|"workdays", holidays: [{date, name}]}` | режим дней (6.19) и список праздников |
| `oati_gantt_showdeps_v1` | `"1"`/`"0"` | показ/скрытие стрелок зависимостей (6.20); по умолчанию показаны |
| `oati_gantt_zoom_v1` | число `0.25…4` | масштаб диаграммы (6.2, 6.24); по умолчанию `1` |
| `oati_gantt_label_w_v1` | число или отсутствует | **ручная ширина колонки названий** (6.1); отсутствие — авто-ширина; UI-настройка, не экспортируется |
| `oati_gantt_executors_v1` | массив `[{id, name, role}]` | **каталог исполнителей** (6.28): справочник ФИО/должности, на который жёстко ссылаются `ownerId`/`execId`/`coId` записей плана |

**`[уточнено, Версия 6]` Ширина колонки названий** — UI-настройка (как масштаб), хранится в `oati_gantt_label_w_v1`; не входит в JSON/CSV и не сбрасывается при импорте или «Новой диаграмме». Двойной клик по ручке возвращает авто-ширину и удаляет ключ.

**`[уточнено, Версия 3]` Фильтры (6.29) не хранятся в localStorage** — это состояние только текущего сеанса. При перезагрузке страницы, успешном импорте и «Новой диаграмме» оба фильтра сбрасываются в «Все». Авто-статус направления также не хранится: он пересчитывается из подзадач при каждом рендере.

**`[уточнено, Версия 4]` `meta.project`** — **название диаграммы** (6.30). Хранится в плане и localStorage, попадает в H1 и `document.title`; при пустом значении используется fallback `"SMART OATI"`. Название участвует в JSON-экспорте (`project`) и CSV-блоке `# project`, но не является частью записей задач.

**`[уточнено, Версия 7]` `meta.depStyles`** — карта стилей связей `{ "from>to": {color, dash, shape} }` (6.31.3). Хранится только для **нестандартных** стилей; по умолчанию записи нет (`color="#94a3b8"`, `dash="solid"`, `shape="orthogonal"`). Ключ — `from>to`; значения нормализуются. Карта чистится при удалении связей/задач/импорте и пересчитывается при перенумерации WBS. Экспортируется в JSON (`depStyles`) и CSV (`# depstyles`).

**`[уточнено]` Возможные значения `meta.source`:**

| Значение | Когда выставляется |
|----------|---------------------|
| `"диаграмма собрана в браузере"` | план наполнялся вручную (fallback, если `meta.source` отсутствует) |
| `"новая диаграмма"` | после нажатия «Новая диаграмма» → «Создать» (§6.23) |
| **имя импортированного файла** (например, `SMART_OATI_диаграмма_Ганта_экспорт_2026-10-23.json`) | после успешного импорта, если имя файла доступно (§6.15) |
| `"импорт из JSON"` / `"импорт из CSV"` | fallback после импорта, если имя файла недоступно (например, `FileReader` не вернул `file.name`) |
| **произвольная человекочитаемая метка** (например, `SMART_OATI_проектный_трекер.xlsx, лист «План работ»`) | план введён внешним инструментом/скриптом, задающим источник; значение отображается как есть, валидации не применяется `[уточнено]` |

Примечание: `meta.source` — человекочитаемая метка, а не закрытый словарь. Приложение не ограничивает её значения: любые строки отображаются в строке периода (п. «Источник») и сохраняются в экспорте. Перечисленные выше значения — типовые, генерируемые самим приложением.

Правило целостности: при удалении записи из плана связанные данные удаляются из `flags`, а при удалении направления — из `dir_order`. При удалении исполнителя из каталога его id остаётся в записях плана как «сирота» — отображается плейсхолдер «—» и пометка, что исполнитель не найден (6.28); сами записи плана **не** удаляются и не чистятся.

**Полное отображаемое множество:** `allData() = plan.tasks` (порядок строк дополнительно учитывает `dir_order`, см. 6.1).

## 5. Слой отображаемых значений

Отдельного хранилища правок (overrides) нет: все поля записи изменяются «на месте» и сразу сохраняются в план (§4). При отображении и экспорте используются:

| Функция | Значение |
|---------|----------|
| `effTask(it)` / `effJira(it)` | соответствующее поле записи: `task` / `jira` |
| `effStatus(it)` | для lvl≥2 — поле `status`; для lvl1 — **расчётный** агрегированный статус (6.29) или `null`, если подзадач нет |
| `effPct(it)` | для lvl≥2 — поле `pct`; для lvl1 — **расчётный** агрегированный процент (6.29) или `null`, если подзадач нет |
| `effOwner(it)` | **ФИО ответственного** = `resolvePerson(it.ownerId)`; `null`/не найден → `null` (отображается как «—») |
| `effExec(it)` / `effCo(it)` | **ФИО исполнителя / соисполнителя** = `resolvePerson(it.execId)` / `resolvePerson(it.coId)`; аналогично `effOwner` |
| `resolvePerson(id)` | `id` → `name` из каталога `oati_gantt_executors_v1`; `null` или id отсутствует в каталоге → `null`. Единая точка разрешения жёстких ссылок (6.28) |
| `effDesc(it)` | поле `desc` записи (пусто по умолчанию); используется в форме, тултипе и экспорте (6.25) |
| `effComments(it)` | поле `comments` записи (пустой массив по умолчанию); используется в счётчике строки, модалке, тултипе и экспорте (6.26) |
| `effDoneDate(it)` | поле `doneDate` записи (`null` по умолчанию); используется в баре, тултипе, карточке и экспорте (6.27); **у lvl1 всегда `null`** |
| `effDeps(it)` | поле `deps` записи (пусто по умолчанию); используется в графе зависимостей (6.20), CPM (6.21), тултипе и экспортах |
| `effStart(it)` | `start` записи |
| `effEnd(it)` | `end` записи; **для направления (lvl1)** — максимум `effEnd` по всем потомкам (lvl≥2 с `rootId == id`); **для задачи (lvl2) с подзадачами** — максимум `effEnd` по её lvl3-потомкам; если потомков нет — `end` записи `[Версия 8]` |
| `effDays(it)` | `(effEnd − effStart)` в днях + 1 (в режиме «Рабочие» — число рабочих дней, 6.19) |
| `descStats(id)` | `{count, maxEnd}`: для lvl1 — все потомки lvl≥2 с `rootId == id`; для lvl2 — lvl3 с `parent == id`; используется для авто-окончания `[Версия 8]` |
| `dirAutoEnd(it)` | `true` для lvl1/lvl2, у которых есть потомки (6.11); управляет disabled правого края бара, авто-окончанием и drag «только начало» |
| `dirKids(dirId)` | массив всех потомков направления: lvl2 с `parent == dirId` + lvl3, чьи родители входят в этот набор |
| `dirAggregate(dirId)` | `{count, status, pct}` — расчётный статус/процент направления по `dirKids` (правила — 6.29); для пустого направления `{count: 0, status: null, pct: null}` |
| **Экспорт lvl1** `[уточнено, Версия 3]` | JSON/CSV выгружают **хранимые** `status`/`percentComplete` (для lvl1 — `null`), а не расчётные; `end` направления по-прежнему выгружается расчётным (по подзадачам) |

`rootId(it)`: lvl1 → `id`; lvl2 → `parent`; lvl3 → `parent.parent` (через поиск родителя).

## 6. Функциональные требования

### 6.1. Рендеринг диаграммы

- Контейнер `.gantt` из строк: заголовочная строка (шкала) + строки по каждому элементу плана (все 3 уровня).
- Порядок строк — `orderedData()`: направления в порядке `dir_order` (независимые — по WBS после), затем за каждое направление его lvl2 по WBS, затем lvl3 каждого lvl2. Остальные записи (сироты) — по WBS в конце.
- Левая колонка — **ширина авто или ручная** (6.1): `[поле порядка (lvl1)] [кнопка ▼/▶ (lvl1 или lvl2 с подзадачами)] [бейдж WBS id] [чип Jira (если есть)] [название (переносится при нехватке места)] [кнопка 💬 N — счётчик комментариев, 6.26; видна, если есть хотя бы один комментарий] [бейдж «скрыто: N» (свёрнутая строка lvl1/lvl2)] [кнопки БП/СП] [＋] [✕ (удаление)] [ручка ресайза ширины]`.
- **Ширина колонки (авто).** По умолчанию `calcLabelWidth(data, counts)` = max по **всем** записям плана (независимо от сворачивания и фильтров) ширины: отступ по уровню (12/28/48) + элементы строки (замер `measureTextW` по шрифту строки: название — шрифт уровня, id — 11px/600, Jira-чип 10px/700, «💬 N» 10px/700 (считается с максимальным по плану счётчиком комментариев, чтобы ширина не «прыгала» при добавлении комментария), «скрыто: N» 10px/600, БП/СП 10px/700, ✕ 34px, gap 8px; для lvl2 с подзадачами учитываются кнопка ▼/▶ и бейдж «скрыто: N»). Нижняя граница 360 px. Значение задаётся CSS-переменной `--label-w` на `.gantt`; `min-width` дорожки 500 px защищает таймлайн. При авто-ширине названия обычно помещаются в одну строку; ширина одинакова в свёрнутом и развёрнутом виде (не «прыгает»).
- **`[уточнено, Версия 6]` Ручная ширина и перенос названий.** Справа от каждой строки (включая заголовок) есть ручка `.label-resizer` (`cursor: col-resize`). Перетаскивание задаёт ручную ширину `manualLabelW` в диапазоне **360 px … (ширина панели − 240 px)**, сохраняет её в `oati_gantt_label_w_v1` и сразу пересчитывает `--label-w`/`--timeline-w`. Двойной клик по ручке возвращает авто-ширину и удаляет ключ. При нехватке места `.label .txt` **переносится на новую строку** (`white-space: normal; overflow-wrap: anywhere`), поэтому строка становится выше; дорожка растягивается по высоте (`min-height: 44px; height: auto`), а бар центрируется (`top: 50%; transform: translateY(-50%)`). При очень узкой ширине служебные элементы (Jira, комментарии, флаги, действия) также могут переноситься на следующую строку (`.label` — `flex-wrap: wrap`), чтобы не перекрывать таймлайн. Escape во время перетаскивания отменяет изменение.
- **`[уточнено, Версия 5]` Закреплённая колонка названий.** `.label` имеет `position: sticky; left: 0; z-index: 6` (заголовочная строка — `z-index: 7`), поэтому при горизонтальной прокрутке колонка названий задач/направлений **остаётся на месте**, а прокручивается только таймлайн. Ширина `--label-w` и шрифты от масштаба не зависят. Вертикальная прокрутка страницы двигает колонку и таймлайн синхронно.
- **Оверлей стрелок** (6.20) позиционируется от `--label-w`.
- Правая часть — дорожка (track) с баром. Дорожка имеет `overflow: hidden`: всё, что выходит за её пределы (бары, подписи, стрелки), обрезается по границам дорожки и **никогда не попадает на колонку с названиями задач**.
- **Бары в границах дорожки:** при отрисовке `left`/`width` бара ограничиваются диапазоном `[0 %, 100 %]` дорожки — задачи, чьи даты выходят за пределы видимого диапазона (например, при зуме, 6.24), рисуются обрезанными по краю, а не поверх списка. Подпись ответственного (`.powner`) при нехватке места переносится внутрь бара, а если не помещается — скрывается.
- **Горизонтальная прокрутка:** нативная полоса панели (`.panel`) скрыта; **над диаграммой** и **под панелью** размещены две синхронные полосы (`.top-scroll` и `.bottom-scroll`, по 15 px): прокрутка любой из них двигает панель, а панель синхронизирует обе. **`[уточнено, Версия 5]`** Обе полосы выровнены по таймлайну: `margin-left = --label-w`, ширина = `calc(100% − --label-w)`, внутренняя ширина = `scrollWidth − labelW` (обычно `timelineW`); таким образом они начинаются после закреплённой колонки названий, а не под ней. Колонка названий при прокрутке не сдвигается. Верхняя полоса закреплена (`position: sticky`) под панелью инструментов (смещение = высота панели инструментов, CSS-переменная `--tb-h`); нижняя находится под панелью. Обе появляются только при горизонтальном переполнении и скрываются в печати.
- **`[уточнено]` Sticky-поведение заголовочной строки:** заголовочная строка (`.row.headrow`) закреплена (`position: sticky`) **внутри панели диаграммы** — это обеспечивает её видимость при **горизонтальной** прокрутке. При **вертикальной** прокрутке страницы панель диаграммы не имеет собственного скролла (нет `max-height`), поэтому заголовок уезжает вместе с диаграммой в обычном потоке документа. Такое поведение выбрано сознательно: диаграмма прокручивается вместе со страницей, а не внутри панели; при необходимости «прилипания» при вертикальной прокрутке в будущем потребуется задать панели `max-height` и пересмотреть UX.
- **`[уточнено, Версия 8]` Свернутая строка** (направление lvl1 или задача lvl2 с подзадачами): её потомки не рендерятся; сама строка остаётся видимой с бейджем «скрыто: N» (для lvl1 — все скрытые lvl2/lvl3; для lvl2 — его lvl3). Кнопка ▼/▶ показывается только у строк, у которых есть потомки.
- **`[уточнено, Версия 3]` Фильтрация (6.29):** при активных фильтрах рендерятся только строки, совпавшие хотя бы с одним фильтром, и **все их предки** (контекст). Контекстные строки получают класс `filter-ctx` и приглушаются (`opacity: .55`). Свёрнутые направления при активных фильтрах **раскрываются** (состояние `collapsed` сохраняется и снова применяется после сброса). Если в непустом плане нет совпадений, выводится строка-подсказка «Нет строк, удовлетворяющих фильтрам…». Ширина колонки, диапазон таймлайна, карточки, CPM и экспорт от фильтров **не зависят**.

### 6.2. Таймлайн (шкала)

- Диапазон: `min = floor(мин(effStart) по всем) − 1 день`, `max = ceil(макс(effEnd) по всем) + 1 день`. Позиция даты — в процентах: `pos(t) = (t − min) / (max − min) × 100`. При пустом плане — дефолтный диапазон «сегодня ±30 дней» (см. 6.23).
- **Ширина таймлайна (пиксельная шкала):** дорожка имеет явную ширину, задаваемую CSS-переменной `--timeline-w` на `.gantt`: `timelineW = baseDays × pxPerDay`, где `pxPerDay = (доступная ширина панели − ширина колонки списка) / baseDays × z` (z — масштаб, 6.24). Ширина строки = колонка списка + дорожка; ширина `.gantt` = `labelW + timelineW` (не менее 1100 px). При z = 1 весь план помещается в ширину панели; при увеличении таймлайн становится шире — панель прокручивается горизонтально.
- Заголовок содержит:
  - **месяцы**: на 1-е число — линия + подпись «Месяц Год»;
  - **недели**: по понедельникам — пунктирная линия + подпись `ДД.ММ`;
  - **`[уточнено]` выходные**: серая подсветка всех сб/вс **в заголовочной строке и на всю высоту таймлайна** (единый сквозной слой над дорожками всех строк данных — визуально то же, что подсветка «в каждой дорожке»; реализация — один слой вместо дубля ячеек в каждой строке, экономия ~N_строк × N_выходных элементов, §9.3) — фон выходных виден по всей высоте диаграммы;
  - **линия «Сегодня»**: оранжевая вертикальная линия на дате открытия файла (00:00 локального времени) + подпись «Сегодня ДД.ММ.» (если дата внутри диапазона).
- Линия «Сегодня» — единый сквозной слой на весь таймлайн (сквозной эффект через все строки; визуально эквивалентно дублю в каждой дорожке).
- Подпись периода: `Период: ДД.ММ.ГГГГ — ДД.ММ.ГГГГ · Источник: … · Наведите курсор на бар для деталей`. **`[уточнено, Версия 4]`** Название диаграммы в этой строке **не дублируется** — оно выводится в H1 (6.30).

### 6.3. Бары

- Бар: абсолютная позиция `left/width` в % от дорожки, по `effStart/effEnd`.
- Цвет по статусу: Выполнено — зелёный, В работе — голубой, Заблокировано — красный, Запланировано — серый; у направления без подзадач — серо-синий «dir». Для направлений цвет, текст и заливка используют **расчётный** статус/процент (6.29): когда все подзадачи выполнены, бар зелёный и показывает «Готово 100%».
- Внутри бара: **заполнение** шириной `pct`% (светлее) и **краткий текст статуса** (чёрный): «Готово 100%», «В работе», «Блок», «Заплан» (если `pct` — с процентом).
- **Бейдж досрочного выполнения** (6.27): у записи с заполненной `doneDate` на баре отображается бейдж «✓ досрочно на N дн.» (N — по текущему режиму дней), если `doneDate` раньше `effEnd`; при `doneDate = effEnd` — бейдж «✓ точно в срок» (без числа дней). Бейдж не выводится, если `doneDate` позже `effEnd` (просрочка бейджем не отмечается — её видно по дате в тултипе и по статусу).
- Слева от бара — **ромб приоритета** (цвет: Критический/Высокий/Средний/Низкий), title с полным значением.
- Справа от бара — **ФИО ответственного** (`effOwner`, разрешение из каталога 6.28; при `null`/сиротской ссылке подпись не выводится). Если справа не помещается — переносится влево от бара; если влево тоже нет места — скрывается.
- **`[уточнено, Версия 6]`** Бары всех уровней вертикально центрируются в строке (`top: 50%; transform: translateY(-50%)`), поэтому при переносе названия и увеличении высоты строки бар остаётся по центру. Уровень 3: `height: 18px`, уровень 1: `height: 24px`, уровень 2: `20px`; отступ в подписи уровня 3 больше.
- Клик по бару — открыть модалку редактирования.

### 6.4. Сводные карточки

Ряд карточек над диаграммой (пересчитывается при каждом рендере):
1. **направлений** — количество lvl1;
2. **задач** — количество lvl≥2;
3. **выполнено / в работе / заблокировано / запланировано** — по статусу задач (lvl≥2);
4. **выполнение (по дням)** — `round( Σ(pct_i × days_i) / Σ(days_i) )` по задачам lvl≥2 (веса — `effDays`);
5. **досрочно** (6.27) — количество задач lvl≥2, у которых `doneDate` заполнено и `doneDate < effEnd` (ранее срока), и среднее сдвигание: `−N дн.` = `round( Σ(effEnd_i − doneDate_i) по этим задачам / количество )` в днях текущего режима. Если таких задач нет — карточка показывает «0».

**`[уточнено, Версия 3]`** Карточки считаются по **полному** плану и **не зависят от фильтров** (6.29): фильтрация меняет только набор отображаемых строк. Направления в карточки статусов/процента не входят (только lvl≥2); авто-статус направления на карточки не влияет.

### 6.5. Сворачивание `[уточнено, Версия 8]`

- Кнопка `▼`/`▶` показывается у **любой строки с потомками**: направления (lvl1, есть lvl2) и задачи (lvl2, есть lvl3). У подзадач (lvl3) кнопки нет.
- Сворачивание направления скрывает все его lvl2/lvl3; сворачивание задачи — только её lvl3. Сама строка остаётся видимой с бейджем «скрыто: N»: N — все скрытые потомки для направления, число lvl3 для задачи.
- ID свёрнутых строк хранятся в `oati_gantt_collapsed_v1`; состояние переживает перезагрузку. Вложенные состояния независимы: свёрнутая задача остаётся свёрнутой после сворачивания/разворачивания родительского направления.
- При активных фильтрах свёрнутость **игнорируется** (ветки раскрываются, чтобы были видны совпадения); клик по `▼/▶` в это время показывает toast и не меняет сохранённое состояние. После сброса фильтров сохранённое состояние применяется снова.
- При удалении строки её ID удаляется из `collapsed`; при перенумерации WBS (6.18.1) ключи пересчитываются; «Новая диаграмма» очищает множество.

### 6.6. Флаги БП / СП

- Кнопки «БП» и «СП» в каждой строке (все уровни); переключают состояние (подсветка зелёным).
- Хранение — `oati_gantt_flags_v1`. Отображаются в тултипе и экспорте (`hasBP`/`hasSP`).

### 6.7. Тултип (наведение на бар)

Всплывающая плашка: `ID · Название`, **Описание** (если `desc`, 6.25), **Срок**: `Д — Д (N дн.)`, **Факт**: `дата (досрочно на N дн. | в срок | просрочка N дн.)` (если `doneDate`, 6.27), **Статус** (цветной) · pct · приоритет, **Ответственный** (+ исполнитель, + соисп.), **Jira** (если есть), **Результат**, **Комментарии**: `N` (если есть, 6.26) + текст последнего комментария в одной строке (обрезка по ~80 символов), **Документы**: есть/нет БП · СП, **Зависит от** (если `deps`). Имена разрешаются из каталога (6.28): если id назначен, но исполнитель **не найден** в каталоге, вместо имени выводится «— (исполнитель не найден)». Позиция — за курсором, с отскоком от краёв окна. **`[уточнено, Версия 3]`** Для направления в строке «Статус» показываются расчётные `effStatus`/`effPct` (6.29); «Факт» у направления не выводится.

### 6.8. Добавление задачи (кнопка «+ Добавить задачу»)

Модалка полей:
- **Родитель** — всплывающее **дерево плана**: «+ Новое направление…» (закреплено сверху), направления (выборочны), lvl2 (выборочны), lvl3 (невыборочны, только для контекста). Текущий выбор отображается на кнопке-переключателе.
- **Название задачи** * (input, **maxlength 200** `[уточнено]`), **Описание** (textarea, необязательное, 6.25), **Начало** *, **Окончание** * (`end ≥ start`), **Статус** (select), **Приоритет** (select, по умолчанию «Высокий»), **Ответственный** (комбобокс из каталога исполнителей, 6.28), **Номер задачи в Jira** (input, maxlength 40), **Результат/критерий** (input, maxlength 200), **Зависимости (ID через «;»)** (input, **maxlength 120** `[уточнено]`).
- Если выбран «+ Новое направление…» — раскрывается поле **Название нового направления** * (обязательное, maxlength 150).

Поведение:
- **Родитель обязателен.** Если в дереве не выбрана ни одна запись (кнопка «+ Добавить задачу» на панели без выбора) — блокирующая ошибка «Выберите родителя в дереве плана: направление, задача или «+ Новое направление…»»; запись не создаётся, модалка остаётся открытой.
- Новое направление создаётся с `nextTopId()`, `parent: null`, `lvl: 1`, статус `null`, приоритет «Высокий»; сразу после него создаётся сама задача (`lvl: 2` под ним), с датой/статусом/приоритетом из формы (`pct = 100`, если статус «Выполнено», иначе `null`).
- **Описание** из формы пишется в `desc` создаваемой задачи (направление создаётся с `desc = null`); при создании из пустого значения `desc = null`.
- **Ответственный** — комбобокс (6.28): выбор из каталога исполнителей **+ пункт «＋ Новый исполнитель…»** (инлайн-создание: раскрываются поля «ФИО*» и «Должность», при сохранении формы исполнитель добавляется в каталог и назначается на создаваемую запись; дубликат ФИО — выбирается существующий, предупреждение; при отмене формы в каталог ничего не пишется). Запись создаётся с `ownerId = id` выбранного исполнителя (у направления — тоже; у задачи `execId`/`coId` = `null`). Пустой выбор → `ownerId = null`.
- **Досрочное выполнение:** при создании записи со статусом «Выполнено» поле `doneDate` заполняется **текущей датой** (правило 6.27); для остальных статусов `doneDate = null`.
- Задача под lvl2 создаётся как `lvl: 3`.
- Jira: **мягкая** валидация — при несоответствии `^[A-Za-z][A-Za-z0-9]*-\d+$` показывается жёлтое предупреждение, но значение сохраняется как введено.
- **Даты:** в режиме «Рабочие» (6.19) даты автоматически приводятся к рабочим дням — начало вперёд, окончание назад; в режиме «Календарные» даты сохраняются как введены.
- Записи добавляются в план (`plan.tasks`), сохраняются, модалка закрывается, рендер обновляется. У каждой строки — кнопка ✕ (удаление) и кнопка «＋» (создание подзадачи прямо из строки, 6.8.1).

### 6.8.1. Создание подзадачи прямо из строки (кнопка «＋»)

- В правой части строки, рядом с кнопкой «✕», размещена кнопка **«＋»** — «добавить подзадачу в эту строку».
- Кнопка отображается **только** у записей `lvl 1` (направление) и `lvl 2` (задача). У `lvl 3` кнопки нет — глубина дерева ограничена тремя уровнями.
- Нажатие открывает ту же модалку добавления (6.8), но **родитель предвыбран** = ID строки, на которой нажата кнопка:
  - «＋» у направления (`lvl 1`) → создаётся задача `lvl 2` (`X.Y`);
  - «＋» у задачи (`lvl 2`) → создаётся подзадача `lvl 3` (`X.Y.Z`).
- Остальные поля — пустые/по умолчанию (статус «Запланировано», приоритет «Высокий»); дерево выбора родителя остаётся доступным — родителя можно перевыбрать вручную.
- После сохранения: запись добавляется в `plan.tasks`, план сохраняется, **родительская строка разворачивается** (ID родителя и корневого направления удаляются из `collapsed`; для подзадачи это и задача lvl2, и направление), новая строка выделяется (`selId`) и отображается в дереве.
- ID новой записи — `nextChildId(parentId)`: следующий свободный номер в ветке (например, `1.1` → `1.2`, `1.1.1` → `1.1.2`).
- **Прокрутка страницы не сбивается:** открытие модалки (фокус на поле «Название задачи») и сохранение не подтягивают документ вверх — текущая позиция скролла сохраняется (`focus({preventScroll:true})` + восстановление `scrollX/scrollY`).

### 6.9. Удаление задачи

- Кнопка ✕ (у любой записи) → `confirm` с названием.
- Каскад: удаляются все потомки (по цепочке `parent`).
- Чистка: записи из `flags`, `dir_order`. Поля `desc`, `comments` и `doneDate` удаляются вместе с записью (они хранятся в самой записи, отдельной чистки не требуется).
- Изменение сразу сохраняется в план. Удаление последней записи оставляет **пустой план** (не сбрасывает остальные настройки и не возвращает приложение в «первый запуск»).

### 6.10. Редактирование (клик по бару)

Модалка: **Название задачи*** (input, **maxlength 200** `[уточнено]`), **Описание** (textarea, необязательное, 6.25), **Ответственный** (комбобокс, 6.28), **Исполнитель** (комбобокс, 6.28), **Соисполнитель** (комбобокс, 6.28), **Номер задачи в Jira** (input, maxlength 40), **Зависимости (ID задач через «;»)** (input, **maxlength 120** `[уточнено]`), **Статус** (select) — **`[уточнено]` скрыто для направлений (lvl1)**, **Процент выполнения** (0–100, step 5) — **`[уточнено]` скрыто для направлений (lvl1)**, **Начало***, **Окончание***, **Факт завершения** (date, 6.27) — **`[уточнено]` скрыто для направлений (lvl1)**, **Комментарии** (кнопка «Комментарии (N)…» → отдельная модалка 6.26), поле ошибок, кнопки «Отмена»/«Сохранить». Escape и клик по фону закрывают. Поля «Исполнитель»/«Соисполнитель» предзаполнены текущими id из каталога; пустой выбор → `null`. Комбобоксы — с пунктом «＋ Новый исполнитель…» (инлайн-создание, 6.28): созданный исполнитель добавляется в каталог и **немедленно** назначается в соответствующее поле; при отмене формы каталог не изменяется.

**`[уточнено]` Правила видимости и нормализации полей для направлений (lvl1):**
- поля **«Статус»**, **«Процент выполнения»**, **«Факт завершения»** скрыты (`hidden`), поскольку в модели данных хранимые `status`/`pct`/`doneDate` у направлений всегда `null` (§3.1); при этом отображение, тултип и фильтры используют **расчётные** статус/процент (6.29);
- при сохранении для lvl1 значения принудительно обнуляются (`it.status = null; it.pct = null; it.doneDate = null`), **даже если в скрытых полях остались старые значения** — это защита от «всплытия» при последующем перетаскивании lvl1 → lvl2 (§6.18.1). В частности, если задача lvl2 с заполненным `status`/`pct`/`doneDate` перетаскивается на lvl1, значения обнуляются при дропе (см. §6.18.1, «Нормализация полей уровня»), и при обратном перетаскивании lvl1 → lvl2 они уже не «воскресают».
- **`[уточнено, Версия 8]`** У задачи lvl2 с подзадачами поле **«Окончание»** отключено и показывается заметка об авто-окончании (6.11); поля «Статус», «Процент», «Факт завершения» остаются доступны.

**Компоновка (без вертикальной прокрутки).** Ширина модалки — **640 px** (не 440). Поля размещаются так, чтобы на типовых экранах (высота ≥ 768 px) вертикальный скролл **не возникал**, в т.ч. в худшем случае (раскрыта одна инлайн-строка «＋ Новый исполнитель…», 6.28, и видны обе авто-заметки 6.11/6.27):
- **Название задачи** и **Описание** — на всю ширину модалки (вверху).
- Остальные поля — в **сетке 2 колонки** (`.grid2`, `grid-template-columns: 1fr 1fr`, межколонный зазор 14 px), в порядке: Ответственный | Исполнитель, Соисполнитель | Jira, Статус | Процент, Начало | Окончание, Факт завершения | Зависимости; кнопка **Комментарии** — на всю ширину (`grid-column: 1 / -1`).
- Инлайн-строки «＋ Новый исполнитель…» (6.28) раскрываются **внутри** своей ячейки сетки (не раздвигают сетку и не уезжают за её пределы).
- Компактный режим (`.modal.compact`): уменьшенные внутренние отступы/поля (padding 12 px, label 4 px/2 px, input 5 px/8 px), `max-height: calc(100vh − 24px)` как резерв. На экранах ниже ~700 px допустимо появление прокрутки (ограничено `max-height`).

Валидации (блокирующие): процент вне 0–100; пустое название; отсутствие даты; окончание раньше начала; для направления с потомками — начало позже **рассчитанного** окончания.

Даты в режиме «Рабочие» (6.19) приводятся к рабочим дням перед сохранением: начало — вперёд, окончание (кроме направления с авто-окончанием) — назад; значения в полях `Начало`/`Окончание` обновляются на скорректированные.

Правила **Факт завершения** (6.27):
- при изменении статуса на «Выполнено» — поле `Факт завершения` **заполняется сегодняшней датой** автоматически (можно затем переписать на другую);
- при заполнении даты позже `effEnd` — **предупреждение** (не блокирующее) «дата позже срока — задача будет считаться с просрочкой»;
- при изменении статуса с «Выполнено» на любой другой — `doneDate` **очищается** (`null`);
- для направлений поле `Факт завершения` **скрыто** (досрочность учитывается только по задачам lvl≥2).

Сохранение: значения пишутся **прямо в объект записи** (`task, desc, ownerId, execId, coId, status, pct, jira, deps, start, end, days, doneDate`), затем `savePlan()`. Отдельного слоя overrides нет; одинаковые значения просто перезаписываются. **Для lvl1** поля `status`/`pct`/`doneDate` принудительно обнуляются (инвариант §3.1).

### 6.11. Автоматическое окончание направления и задачи с подзадачами `[уточнено, Версия 8]`

- `effEnd(направление lvl1)` = **последняя дата окончания среди всех его потомков (lvl2 и lvl3)**; для lvl2-потомков используется их эффективное окончание (авто-окончание по их lvl3, если есть).
- `effEnd(задача lvl2 с подзадачами)` = **последняя дата окончания среди её lvl3-подзадач**. Если lvl3 нет — `end` записи.
- В модалке направления с подзадачами поле «Окончание» **отключено** и показывается заметка «Окончание, статус и процент направления рассчитываются автоматически по подзадачам» (статус/процент — 6.29). В модалке задачи с подзадачами поле «Окончание» также **отключено**, заметка — «Окончание задачи рассчитывается автоматически по самой поздней подзадаче»; статус/процент задачи остаются редактируемыми.
- При сохранении поле `end` для lvl1/lvl2 с подзадачами **не изменяется**; отображаемые/экспортируемые окончание и дни — расчётные. Если подзадач не осталось, снова используется сохранённый `end`.
- **Бар и drag:** у строки с авто-окончанием правая ручка бара отключена (`.bar-resize.r.disabled`, `cursor: not-allowed`); при попытке потянуть правый край — toast «Окончание направления/задачи рассчитывается автоматически…». Перетаскивание тела/левой ручки меняет только начало; окончание следует за подзадачами. Клавиатурные `←/→/Shift/Home` также меняют только начало.
- Пересчёт автоматический: при изменении дат подзадач, добавлении/удалении подзадач и при переносе/перенумерации.

### 6.12. Jira

- Поле в форме добавления и в модалке редактирования (maxlength 40).
- В строке — синий чип `OATI-123` рядом с WBS; в тултипе — отдельная строка; в экспорте — поле `jira`.
- Пустое значение = без ссылки.

### 6.13. Порядок направлений

- У каждого направления — **числовое поле** с текущей позицией (1…N).
- При изменении значения направление перемещается на указанную позицию (вне диапазона — подрезается), остальные сдвигаются; **перенумерация автоматическая** после рендера.
- Полный порядок сохраняется в `oati_gantt_dir_order_v1` (явный список ID).
- Новое направление (не в списке) ставится в конец; удалённое — вычищается из списка.
- Подзадачи следуют за своим направлением (см. `orderedData()`).

### 6.14. Экспорт в JSON

- Кнопка «Экспорт в JSON» → скачивается `SMART_OATI_диаграмма_Ганта_экспорт_ГГГГ-ММ-ДД.json` (Blob + objectURL).
- Содержимое — **актуальное состояние плана** в порядке отображения: все поля (название, описание, `ownerId`/`execId`/`coId` (жёсткие ссылки, 6.28), статус, pct, даты, дни, `doneDate`, `comments`), `directionOrder`, **`executors` (весь каталог исполнителей, 6.28)**, **`depStyles` (стили связей, 6.31.3)**, `hasBP`/`hasSP`.
- **`[уточнено, Версия 3]`** Для направлений (lvl1) `status` и `percentComplete` выгружаются как `null` — это **хранимые** поля; расчётный авто-статус/процент (6.29) не экспортируется и всегда пересчитывается из подзадач. **`[Версия 8]`** `end` направления и lvl2-задачи с подзадачами выгружается расчётным (по подзадачам); `days` — по расчётному окончанию.
- **`[уточнено, Версия 7]`** `depStyles` — карта нестандартных стилей связей (6.31.3); выгружается как есть; при импорте отсутствие поля сбрасывает стили в `{}`.
- Метаданные: `project` (название диаграммы, 6.30), `source`, `exportedAt`, `today`, `count`.

### 6.15. Импорт из JSON

- Кнопка «Импорт из JSON» → выбор файла → **валидация** → отчёт в модалке:
  - **ошибки** (блокируют импорт): не-JSON; нет объекта верхнего уровня; пустой `tasks`; запись не объект; нет/дублируется `id`; нет названия; некорректные даты (формат `ГГГГ-ММ-ДД`); окончание раньше начала; `doneDate` некорректного формата (6.27).
  - **предупреждения** (не блокируют): уровень выведен из ID; lvl≥2 без `parentId`; неизвестный статус (принят без статуса); процент вне 0–100 (ограничен); `days` не совпадает с расчётным; родитель не найден; `comments` не является массивом (принято пустым); комментарий без текста (пропущен); `doneDate` позже `end` (принята как есть — задача будет отображаться как с просрочкой); `doneDate` при статусе не «Выполнено» (принята как есть); `ownerId`/`execId`/`coId` отсутствует в каталоге (принято как есть — «исполнитель не найден»); строковые `owner`/`executor`/`coexecutor` (старый формат) — нормализованы в id (созданы недостающие записи каталога); записи `executors` с пустым именем/дубликатами (пропущены).
- Кнопка «Применить» активна только при `ok`: `plan = {tasks, meta}` сохраняется в `oati_gantt_plan_v1` (**заменяет текущий план целиком**); флаги восстанавливаются из `hasBP`/`hasSP`; `dir_order` — из `directionOrder` (только валидные ID); **каталог исполнителей** — из блока `executors` (заменяет текущий; при отсутствии блока — не меняется, 6.28); все записи плана проходят **нормализацию ссылок** (3.4): `ownerId`/`execId`/`coId` либо строковые `owner`/`executor`/`coexecutor` → только id; **`meta.depStyles`** — из файла, с очисткой orphan-стилей (6.31.3); **фильтры статуса/ответственного сбрасываются в «Все»** (6.29.2); режим «Связать» выключается (6.31.1).
- **`[уточнено]` Блок `workdays`:** если в файле присутствует — восстанавливается (`mode` + `holidays`); если **отсутствует** — режим сбрасывается на `{mode: "calendar", holidays: []}` (согласно §6.19 и §7).
- **`[уточнено]` `meta.source`:** после успешного импорта выставляется **имя импортированного файла** (например, `SMART_OATI_диаграмма_Ганта_экспорт_2026-10-23.json`); если имя файла недоступно (например, `FileReader` не вернул `file.name`) — fallback `"импорт из JSON"` / `"импорт из CSV"` (см. §4, «Возможные значения `meta.source`»).
- **`[уточнено, Версия 3]`** `status`/`percentComplete`/`doneDate` направлений из внешнего файла по-прежнему игнорируются с предупреждением (§3.1). Файлы, созданные экспортом этого приложения, таких значений для lvl1 не содержат, поэтому обычный round-trip проходит без предупреждений.
- **`[уточнено, Версия 4]` `project` (название диаграммы):** если в JSON есть непустое `project`, оно становится названием; если поле отсутствует или пустое — сохраняется текущее название диаграммы (6.30).
- Строка состояния показывает: количество задач в плане и последний источник (значение `meta.source`). При активных фильтрах дополнительно выводится `показано: X из Y` и состав фильтров (6.29).

### 6.18. Перетаскивание баров (drag & drop)

- **Сдвиг дат мышью** по бару (кроме направления с авто-окончанием — см. ниже): `mousedown` на бар → перетаскивание → ghost-превью (исходный бар затемняется, новая позиция подсвечивается) → отпускание фиксирует новые `start`/`end` с сохранением длительности.
- **Привязка (snap)** — к календарным дням в режиме «Календарные» (6.19) или к рабочим дням в режиме «Рабочие» (6.19, «Приведение дат к рабочим дням»: при сдвиге бара начало и окончание — рабочие дни, а количество рабочих дней задачи сохраняется).
- **Изменение длительности** — за «ручки» на левом и правом краях бара (cursor: ew-resize, зона ~6 px): тянется только начало или только конец, длительность пересчитывается.
- **Подпись превью** у курсора во время перетаскивания: `новая: ДД.ММ — ДД.ММ · N дн.`.
- **Отмена** — `Escape` или правая кнопка мыши (позиция возвращается).
- **`[уточнено, Версия 8]` Строка с авто-окончанием** (направление lvl1 или задача lvl2 с подзадачами): перетаскивание допускает **только сдвиг начала** (ручка и сдвиг конца запрещены — окончание рассчитывается по подзадачам, 6.11). Правая ручка бара рендерится **в отключённом виде** (класс `.disabled`, `cursor: not-allowed`); при попытке потянуть правый край показывается toast «Окончание направления/задачи рассчитывается автоматически по самой поздней подзадаче — тянуть правый край нельзя», перетаскивание не начинается. Строка без подзадач перетаскивается полностью.
- **Результат дропа** пишется прямо в запись плана (`start`/`end`/`days`), затем `savePlan()` и `renderAll()` (шкала и авто-окончания пересчитываются).
- **`[уточнено]` Клик без перетаскивания:** если перемещение курсора за время нажатия **< 3 px** — интерпретируется как клик (открывается модалка редактирования). Порог задан в пикселях (а не в днях), чтобы одинаково работать на любом масштабе (6.24) и не зависеть от `pxPerDay`. При больших зумах 3 px — это доли дня; при малых — несколько часов; в обоих случаях визуально неотличимо от клика.
- **Клавиатурная альтернатива** (доступность): выбранная строка (клик по подписи) + `←/→` — сдвиг на 1 день, `Shift+←/→` — на 7 дней, `Home` — сегодня. В режиме «Рабочие» (6.19) даты подстраиваются под рабочие дни (длительность в рабочих днях сохраняется).
- **Ограничения:** `end ≥ start` (при нарушении — snap не допускает); шкала пересчитывается после дропа, если новый диапазон вышел за границы.
- **Touch:** по желанию реализации — аналог через `touchstart/touchmove/touchend`; минимум — не ломать прокрутку.

### 6.18.1. Перетаскивание строк дерева (перенос задач, drag & drop)

- **Захват:** `mousedown` по наименованию (`.txt`) любой строки (направление / задача / подзадача). Порог сдвига ~4 px; меньше порога — обычное выделение строки (модалка не открывается). Во время переноса исходная строка затемняется (`.drag-src`), у курсора — превью с подсказкой действия.
- **Зоны дропа** задаются по вертикальной позиции курсора внутри строки-цели: верхние ~30 % — **перед** строкой, нижние ~30 % — **после**, середина — **внутрь** (сделать дочерней). Строка-цель подсвечивается (`drop-before` / `drop-after` / `drop-inside`).
- **Семантика дропа:**
  - **«внутрь»** → переносимая запись становится последним ребёнком цели (`parent` = цель, `lvl` = цель + 1);
  - **«перед» / «после»** → запись становится соседом цели (`parent` = родитель цели, `lvl` = уровень цели) и вставляется непосредственно перед/после неё.
- **Что можно переносить:** задачи и подзадачи (в т.ч. смена вложенности вверх/вниз) и направления (переупорядочивание направлений, а также вложение в другое направление, если глубина позволяет).
- **Ограничения (тогда дроп не выполняется, индикатор не показывается):**
  - нельзя бросить на себя или на своего потомка (защита от циклов);
  - глубина дерева ≤ 3: перенос допустим, только если `maxLvl(поддерева) + (newLvl − lvl) ≤ 3` (нельзя бросать «внутрь» строки lvl3).
- **Перенумерация WBS:** после успешного дропа весь план пересобирается в порядке отображения (направления — в текущем порядке `dir_order`, дети — по WBS), и **всем записям выдаются новые ID** `1..D`, `X.Y`, `X.Y.Z`; `lvl` и `type` приводятся к новой глубине.
- **Перенос ссылок:** вместе с ID пересчитываются `deps` (ID предшественников → новые), ключи `flags` и множество `collapsed`; `selId` обновляется; `dir_order` очищается (порядок уже закодирован в ID). Ссылки на исполнителей (`ownerId`/`execId`/`coId`) **не** зависят от WBS-ID и переносятся с записью как есть.
- **`[уточнено]` Нормализация полей уровня:** при переносе записи на **lvl1** (направление) поля `status`, `pct`, `doneDate` принудительно обнуляются (`null`) — они не используются у направлений (§3.1); это защищает от «всплытия» старых значений при обратном перетаскивании lvl1 → lvl2. При переносе lvl1 → lvl≥2 значения остаются `null` (у направления их не было). При переносе между lvl2/lvl3 значения сохраняются как есть.
- **`[уточнено, Версия 8]` Разворачивание свёрнутой строки:** при дропе «внутрь» свёрнутого направления или задачи с подзадачами (`collapsed` содержит её ID) строка автоматически разворачивается (ID удаляется из `collapsed`), чтобы результат переноса был виден пользователю. Это согласуется с поведением создания подзадачи из строки (§6.8.1), где родительское направление тоже разворачивается.
- **Результат дропа:** `savePlan()`, `saveFlags()`, `saveCollapsed()`, `saveDirOrder()`, `renderAll()`; авто-окончания направлений и задач с подзадачами (6.11) и CPM (6.21) пересчитываются автоматически.
- **Отмена:** `Escape` во время переноса — дроп отменяется, план не изменяется.

### 6.19. Режим «Рабочие дни»

- **Переключатель** в шапке: «Дни: Календарные | Рабочие». Состояние персистентно (`oati_gantt_workdays_v1`, см. §4).
- **Режим «Календарные» (по умолчанию):** все расчёты дней — календарные.
- **Режим «Рабочие»:** рабочий день = пн–пт, за вычетом списка праздников.
- **Список праздников:** редактируемая модалка (дата `ГГГГ-ММ-ДД` + имя, удаление строки). По умолчанию пуст; опционально — пресет «Праздники РФ» за текущий и следующий год (затягивается одной кнопкой).
- **Что меняется в режиме «Рабочие»:**
  - `effDays` = количество рабочих дней в `[start..end]` (включительно);
  - сводка «выполнение (по дням)» использует те же рабочие веса;
  - **даты не попадают на выходные/праздники** — подстройка при добавлении, редактировании и перетаскивании (см. «Приведение дат к рабочим дням» ниже);
  - тултип: `N раб. дн.` (и `M кал. дн.` в скобках, если отличается);
  - **шкала времени (min/max, pos%) не меняется** — координаты всегда календарные, меняется только метрика дней и snap.
- **Авто-окончание направления/задачи с подзадачами не меняется** (максимум дат окончания подзадач, а не дней).
- **Экспорт/импорт:** в JSON и CSV выгружается блок `workdays` (см. §7); при импорте восстанавливается. **`[уточнено]`** Если блок `workdays` в импортируемом файле **отсутствует** — режим сбрасывается на `{mode: "calendar", holidays: []}` (см. §6.15, §7).

**Приведение дат к рабочим дням (режим «Рабочие»).** Начало и окончание задачи не должны попадать на выходные/праздники. Подстройка выполняется при любом изменении дат — добавлении (6.8, 6.8.1), редактировании в модалке (6.10) и перетаскивании бара (6.18):
- **Начало** — всегда сдвигается **вперёд** до ближайшего рабочего дня.
- **Окончание** — при вводе/редактировании в форме — **назад** к последнему рабочему дню внутри интервала (не удлиняет задачу); при перетаскивании правого края — **вперёд** до ближайшего рабочего дня.
- **Перетаскивание бара (сдвиг)** — начало снапится вперёд, а окончание вычисляется как день, на который приходится **то же количество рабочих дней**, что было у задачи до переноса (длительность в рабочих днях сохраняется).
- **Ограничения:** `end ≥ start`; для строки с авто-окончанием (направление lvl1 или задача lvl2 с подзадачами, 6.11) меняется только начало, окончание рассчитывается по подзадачам.
- **Автоматичность:** подстройка выполняется молча, без дополнительного подтверждения; скорректированные значения сразу видны в таблице и в тултипе (в форме поля дат обновляются до сохранения).
- **Импорт** даты файла не подстраивает (данные импортируются как есть); подстройка применяется только при ручном добавлении/редактировании и перетаскивании.

### 6.20. Стрелки зависимостей (finish → start)

- **Источники рёбер:** поле `deps` записи (список ID предшественников через `"; "`; редактируется в модалке 6.10, через режим «Связать» и редактор связи 6.31, переносится в экспорт/импорт). Ребро: `предшественник → текущая задача`.
- **Слой рендеринга:** SVG-оверлей на дорожках (absolute, `pointer-events: none`), под барами, над сеткой; перерисовывается при каждом `renderAll()`. **`[уточнено, Версия 7]`** В оверлее для каждого ребра есть невидимая «хит-линия» (толщина 10 px, `pointer-events: stroke`) — по ней открывается редактор связи (6.31.2); она лежит под барами, поэтому бары остаются кликабельными.
- **`[Версия 9]` Подсветка при наведении:** при наведении на хит-линию подсвечиваются **обе строки** связи (класс `dep-hl`: голубой фон `.label` и синий контур бара) и **сама линия** (класс `dep-hover`: толщина 3.5 px + тень). Снятие — при `mouseout`, уходе курсора из диаграммы или открытии редактора. Подсвечиваются задачи любого уровня (включая направления); скрытые/отфильтрованные строки не участвуют, т.к. их бары/стрелки не рендерятся.
- **Видимость:** чекбокс «Стрелки зависимостей» в панели инструментов показывает/скрывает весь слой оверлея; состояние сохраняется в `oati_gantt_showdeps_v1` (по умолчанию — вкл). Скрытие не влияет на расчёты CPM/резервов (тултип и карточка остаются); при скрытых стрелках редактировать связь кликом нельзя.
- **Геометрия:** по умолчанию ортогональная полилиния: правый конец бара предшественника → короткий выступ → вертикаль → левый край бара последующей. **`[уточнено, Версия 7]`** Форма настраивается в редакторе связи: `orthogonal` (по умолчанию), `straight` (прямая), `curved` (кубическая кривая); стрелка-наконечник у конца. Для всех форм строится хит-линия.
- **Стиль:** по умолчанию линия 1.5 px, цвет `#94a3b8`, сплошная, наконечник-треугольник. **`[уточнено, Версия 7]`** Цвет, штрих (`solid`/`dashed`/`dotted`) и форма настраиваются для каждой связи (6.31.3), сохраняются в `meta.depStyles`; наконечник перекрашивается под цвет линии. Для критических связей цвет `#0f172a` и толщина 2.5 px, для нарушенных/циклов — красный `#dc2626` (цвет статуса имеет приоритет над пользовательским; для циклов штрих принудительно `4 3`).
- **Нарушение зависимости** (`effStart(потомок) < effEnd(предшественник) + 1 день`): стрелка красная `#dc2626`, в тултипе строки добавляется `⚠ зависит от X (окончание позже начала)`.
- **Циклы:** DFS по графу зависимостей; при обнаружении — рёбра цикла красные + предупреждение в строке состояния (`цикл зависимостей: A → B → A`); CPM (6.21) при цикле не рассчитывается. Добавление связи, создающей цикл, не блокируется — граф и строка состояния предупреждают.
- **Самоссылка** (свой ID в `deps`): игнорируется + предупреждение в тултипе; через граф самосвязь не создаётся (6.31.1).
- **Отсутствующий предшественник** (ID не найден в плане): ребро не рисуется, предупреждение в тултипе (совпадает с валидацией импорта).
- Зависимости разрешены для любого уровня и правятся прямо в записи (в том числе у направлений) через поле «Зависимости» в модалке 6.10. **`[уточнено, Версия 7]`** Альтернативные способы — режим «Связать» (6.31.1) и редактор связи по клику на стрелку (6.31.2).

### 6.21. Критический путь (CPM)

- **Алгоритм:** forward pass (ES/EF) + backward pass (LS/LF) по ациклическому графу (6.20). Длительность узла — `effDays` (в текущем режиме дней). Узлы — все записи lvl≥2 и направления (как корни; длительность направления = от его `effStart` до `effEnd`, т.е. до авто-окончания; у lvl2-задачи с подзадачами — до её расчётного `effEnd`, 6.11).
- **Критический путь** — цепочка с нулевым полным резервом (total float) от старта проекта до финиша.
- **Визуализация:** бары критических задач — контур 2 px тёмный (`#0f172a`) + ромбик «КП» у левого края; стрелки вдоль критической цепочки — утолщённые тёмные (2.5 px, `#0f172a`).
- **Сводка:** новая карточка «критический путь: N дн.» (N = длительность пути в текущем режиме дней).
- **Тултип:** для каждой задачи строка `резерв: N дн.` (total float); у критических — `критическая (резерв 0)`.
- **При цикле** зависимостей — CPM не рассчитывается, карточка показывает «—», строка состояния содержит предупреждение о цикле.
- **Пересчёт:** при любом изменении (даты, зависимости, добавление/удаление, режим дней, порядок не влияет).
- **Сложность:** O(V·E), достаточно для ≤ 1000 записей; вычисление выполняется в `renderAll()` до отрисовки баров.

### 6.22. Импорт/экспорт CSV

- **Экспорт CSV:** отдельная кнопка «Экспорт в CSV» (рядом с JSON). Файл `SMART_OATI_диаграмма_Ганта_экспорт_ГГГГ-ММ-ДД.csv`, кодировка **UTF-8 с BOM**, разделитель `;` (русский Excel), строки в порядке отображения, текущие значения. После таблицы выводятся блоки `# project <название>`, `# depstyles …`, `# workdays …` и `# executors …` (6.30, 6.31.3, 6.19, 6.28).
- **Колонки (порядок фиксирован):** `WBS ID; Наименование; Родитель; Уровень; Тип; Владелец; Исполнитель; Соисполнитель; Начало; Окончание; Дни; Рабочие дни; Статус; Процент; Приоритет; Jira; БП; СП; Зависимости; Результат; Описание; Факт завершения; Досрочно (дн.); Комментарии`. Даты — `ГГГГ-ММ-ДД`; пустые значения — пустые ячейки. `Досрочно (дн.)` — N дней (в текущем режиме), если `doneDate < end`, иначе пусто; `Комментарии` — тексты через ` | ` (вместе с датами: `ДД.ММ.ГГГГ: текст | …`). **`[уточнено, Версия 3]`** У направлений колонки «Статус» и «Процент» пусты: выгружаются хранимые значения (`null`), расчётный авто-статус (6.29) не экспортируется. **`[Версия 8]`** Для направлений и lvl2-задач с подзадачами «Окончание» и «Дни» выгружаются расчётными (6.11).
- **Импорт CSV:** отдельная кнопка «Импорт из CSV» в модалке импорта (вкладка/файловый ввод). Разделитель — автоопределение (`;` или `,`) по первой строке. Заголовки сопоставляются нечувствительно к регистру по синонимам (`id`/`WBS ID`/`WBS`; `task`/`Наименование`/`Название`; `start`/`Начало`; и т.п.).
- **Валидация** — та же, что у JSON (6.15): ошибки блокируют, предупреждения нет. Особенности: процент принимает 0–100; значение `0 < x < 1` трактуется как доля (×100, предупреждение); **`[уточнено]` `БП/СП` — булевы (`1/0`, `да/нет`, `есть/нет`, `yes/no`, `true/false`; без учёта регистра; пустое = `false`)**; `Рабочие дни` и `Досрочно (дн.)` при импорте игнорируются (пересчитываются из режима и праздников / из `doneDate` и `end`); `Комментарии` разбираются по ` | ` (дата необязательна — без даты `createdAt = null`, автор — пустой); `Описание` и `Факт завершения` (синонимы «Факт», «Дата завершения») принимаются как в JSON. **Исполнители** (6.28): колонки `Владелец`/`Исполнитель`/`Соисполнитель` — **имена**; при импорте имя связывается с каталогом (сначала с импортированным из строки `# executors`, затем с текущим; trim, регистр не учитывается) → `ownerId`/`execId`/`coId`; имя не найдено → создаётся новая запись каталога. Строка `# executors` после таблицы (формат `ФИО (Должность); ФИО2 (Долж2); …`; должность в скобках необязательна) при импорте **заменяет** каталог; при отсутствии строки каталог не меняется.
- **Применение** — идентично JSON-импорту: план заменяется целиком, флаги восстанавливаются из колонок БП/СП, `dir_order` — по WBS (в CSV порядок = порядок строк файла, принимается как есть при сохранении исходной нумерации ID). **`[уточнено]` Блок `# workdays`:** если присутствует — восстанавливается; если отсутствует — режим сбрасывается на `{mode: "calendar", holidays: []}` (аналогично §6.15, §6.19). **`[уточнено]` `meta.source`:** выставляется имя CSV-файла (или fallback `"импорт из CSV"`, см. §6.15). **`[уточнено, Версия 4]` Блок `# project`:** если присутствует — становится названием диаграммы; если отсутствует или пуст — сохраняется текущее название (6.30). **`[Версия 7]` Блок `# depstyles`:** если присутствует — стили связей восстанавливаются; если отсутствует — `meta.depStyles = {}`. Невалидные записи игнорируются; стили для несуществующих рёбер отбрасываются (6.31.3/6.31.4).
- **Совместимость:** CSV-экспорт открывается в Excel без артефактов (BOM + `;`); CSV из Excel с кириллическими заголовками импортируется.

### 6.23. Новая диаграмма (очистка плана)

- Кнопка «Новая диаграмма» → модалка с пояснением последствий и полем **«Название новой диаграммы»** (6.30); по умолчанию в поле подставлено `«Новая диаграмма»`, значение выделено для быстрой замены. Кнопки «Отмена» / «Создать».
- Модалка перечисляет, что будет очищено **в этом браузере**: весь план (все задачи вместе с описаниями, комментариями и фактическими датами завершения), **каталог исполнителей**, флаги БП/СП, порядок направлений, свёрнутые группы и **стили связей**; режим дней → «Календарные», праздники очищаются. Перед созданием предлагается сохранить план кнопкой «Экспорт в JSON».
- **Условие подтверждения:** если в плане есть записи — дополнительный `confirm`; при пустом плане создание происходит сразу.
- **Что делает «Создать»:** `plan = {tasks: [], meta: {project: <введённое имя или "Новая диаграмма">, source: "новая диаграмма", depStyles: {}, updatedAt}}` → `savePlan()`; `executors=[]` → `saveExecutors()`; `flags={}`; `collapsed=∅`; `dirOrder=[]`; `workdays={mode:"calendar", holidays:[]}`; **фильтры статуса/ответственного → «Все»** (6.29.2); режим «Связать» выключается (6.31.1); H1/`document.title` обновляются по новому названию (6.30); перерисовка (`renderModeBtns` + `renderAll`).
- **Пустой план:** `allData()` возвращает `[]`; `recalcRange` задаёт дефолтный диапазон (сегодня ±30 дней), чтобы шкала отрисовалась; в таблицу выводится строка-подсказка «План пуст. Нажмите «+ Добавить задачу» и выберите «+ Новое направление…»»; сводка/CPM показывают нули; стрелки не рисуются.
- **Персистентность:** пустой план сохраняется в `oati_gantt_plan_v1`; после перезагрузки остаётся пустым (не «оживает»).
- **Наполнение:** новые направления создаются через «+ Добавить задачу» → «+ Новое направление…»; `nextTopId()` на пустом плане = `"1"`.

### 6.24. Масштаб диаграммы (zoom)

- **Назначение:** изменение масштаба **только временной шкалы** (диаграммы). Ширина колонки списка задач (`--label-w`), шрифты и состав строк **не меняются от зума** (ширину можно менять вручную, 6.1). **`[уточнено, Версия 5]`** Колонка названий закреплена (`position: sticky; left: 0`) и не участвует в горизонтальной прокрутке; зум не меняет её ширину.
- **Управление** в панели инструментов: кнопки «−» и «+» и кликабельная подпись с текущим процентом (клик — сброс к 100 %). На крайних уровнях соответствующая кнопка блокируется.
- **Уровни:** `0.25, 0.5, 0.75, 1, 1.5, 2, 3, 4` (по умолчанию `1`). Шаг — соседний уровень списка.
- **Как считается:** диапазон дат **всегда полный** (по данным плана, 6.2) — меняется **пиксельная ширина таймлайна**: `pxPerDay = (доступная ширина панели − ширина колонки списка) / baseDays × z`, `timelineW = baseDays × pxPerDay` (снизу ограничена 500 px — `min-width` дорожки, 6.1). Ширина дорожки задаётся CSS-переменной `--timeline-w`; `--label-w` при зуме не меняется.
- **Что пересчитывается:** ширина дорожки и всего `.gantt` (`--timeline-w`), шкала (месяцы/недели/выходные), позиции баров, линия «Сегодня» и оверлей стрелок (все через `pos()`); `min/max/span` — по данным плана, от масштаба не зависят.
- **Прокрутка:** при z > 1 таймлайн шире панели → включается горизонтальная прокрутка (выровненные по таймлайну верхняя и нижняя полосы, 6.1); при z < 1 таймлайн сужается и прокрутка не требуется. **`[уточнено, Версия 5]`** Прокручивается только область таймлайна; закреплённая колонка названий не сдвигается, нативная полоса панели скрыта. Видимая ширина таймлайна = `panel.clientWidth − --label-w`; обе полосы начинаются после колонки названий.
- **Центр вида сохраняется:** при смене масштаба дата в центре видимой области таймлайна остаётся на месте. **`[уточнено, Версия 5]`** Центр — середина видимого пересечения таймлайна с областью без колонки названий: `vis = panel.clientWidth − labelW`, `x = (max(0, scrollLeft) + min(timelineW, scrollLeft + vis))/2`; при установке — `scrollLeft = xTarget − vis/2` с клампингом. При переполнении это эквивалентно `scrollLeft + vis/2`.
- **Перетаскивание баров** использует фактические пиксели на день (`track.clientWidth / span`), поэтому сдвиг мышью точно соответствует датам на любом масштабе.
- **При малом масштабе** (день < ~6 px) подписи недель скрываются, чтобы не накладываться; подсветка выходных сохраняется.
- **За границы видимого диапазона бары не выходят:** задачи вне диапазона рисуются обрезанными по краю дорожки и не перекрывают колонку с названиями (см. 6.1).
- **Персистентность:** уровень хранится в `oati_gantt_zoom_v1` (§4); при отсутствии/некорректном значении — 100 %.

### 6.25. Описание задачи или направления

- **Назначение:** свободный текст, поясняющий суть задачи/направления, её содержание и контекст (в отличие от `result` — «Результат/критерий готовности», который фиксирует измеримый результат).
- **Поле:** `desc` записи плана (string, `null` = пусто, 3.1). Редактируется для **всех уровней** (направление / задача / подзадача).
- **Ввод:**
  - при добавлении — поле «Описание» (textarea, необязательное) в модалке 6.8; пустое значение → `desc = null`;
  - при редактировании — поле «Описание» (textarea) в модалке 6.10, предзаполнено текущим значением; редактирование **в любой момент** (в том числе многократно) без ограничений по числу правок.
- **Отображение:**
  - **тултип** (6.7): строка «Описание» — только если `desc` заполнено;
  - в строке диаграммы и на баре текст **не** отображается (колонтитул не расширяется).
- **Экспорт/импорт:** JSON — поле `description` (6.14/6.15, §7); CSV — колонка «Описание» (6.22). Пустое при экспорте — `null` / пустая ячейка.
- **Ограничения:** максимум 2000 символов (длинный текст обрезается с предупреждением при сохранении); при вставке в HTML — `esc()`.
- **Перенос WBS** (6.18.1): `desc` переносится вместе с записью на новый ID автоматически (поле записи, ссылки на него отсутствуют).

### 6.26. Комментарии к задаче или направлению

- **Назначение:** журнал комментариев/примечаний к записи — обсуждение, решения, ссылки на совещания; доступен для **всех уровней** (направление / задача / подзадача).
- **Хранение:** поле `comments` записи — массив `{id, text, author, createdAt, updatedAt}`:
  - `id` — уникальный инкрементный ID комментария в пределах записи (`c1`, `c2`, …);
  - `text` — текст комментария (непустой, до 2000 символов);
  - `author` — автор (необязательное, строка; если пусто — в выводе «—»);
  - `createdAt` / `updatedAt` — даты `ГГГГ-ММ-ДД` (создание / последняя правка; при создании совпадают, при правке `updatedAt` = текущая дата, `createdAt` сохраняется).
- **Интерфейс:**
  - **в строке** — кнопка «💬 N» рядом с названием (6.1): N = количество комментариев; видна **только** при N > 0; кликабельна — открывает модалку комментариев этой записи;
  - **в модалке редактирования** (6.10) — кнопка «Комментарии (N)…», открывающая ту же модалку.
- **Модалка комментариев:** список комментариев **по возрастанию `createdAt`**; у каждого: дата создания, автор, текст, при правке — «изм. ДД.ММ.ГГГГ», кнопки «✎ Изменить» и «✕ Удалить» (с `confirm`). Сверху — форма добавления: **Текст*** (textarea) + **Автор** (по умолчанию — ФИО ответственного записи `effOwner`, 6.28; можно переопределить) + кнопки «Добавить» / «Закрыть».
- **Редактирование** (требование пункта): «✎» переводит комментарий в режим правки (textarea с текущим текстом + «Сохранить»/«Отмена»); при сохранении `updatedAt` = сегодня, `createdAt` и порядковое место не меняются.
- **Удаление** — `confirm`; после удаления N в строке пересчитывается; при N = 0 кнопка «💬» в строке исчезает, `comments` записи → `null`. **`[уточнено]`** Пересчёт N в строке выполняется при закрытии модалки комментариев (любым способом: кнопка «Закрыть», клик по фону, Escape) — вызывается `renderAll()`.
- **Пустое значение** заблокировано (текст после trim ≠ пусто).
- **Отображение:** тултип (6.7) — строка «Комментарии: N» + текст **последнего** комментария (обрезка ~80 символов, с датой); PDF/печать — комментарии **не** выводятся (только счётчик в строке).
- **Экспорт/импорт:** JSON — поле `comments` (массив объектов §7); CSV — колонка «Комментарии» (`ДД.ММ.ГГГГ: текст | …`). Импорт JSON: не-массив → `null` + предупреждение; комментарии без `text` пропускаются с предупреждением; отсутствующие `id`/`createdAt` довычисляются. Импорт CSV: разбор по ` | ` (6.22).
- **Перенос WBS** (6.18.1): `comments` переносится вместе с записью на новый ID автоматически.
- **Чистка:** при удалении записи (6.9) комментарии удаляются вместе с ней.

### 6.27. Учёт досрочного выполнения

- **Назначение:** фиксация **фактической** даты завершения задачи и расчёт того, насколько она выполнена **досрочно** (ранее срока).
- **Поле:** `doneDate` записи — фактическая дата завершения, `ГГГГ-ММ-ДД` или `null` (3.1). Устанавливается **только для задач lvl≥2** (подзадачи lvl3 включены; у направлений lvl1 не ведётся — в модалке 6.10 поле скрыто).
- **Правила установки:**
  - при изменении статуса на **«Выполнено»** (добавление 6.8 или редактирование 6.10) — `doneDate` автоматически заполняется **текущей датой**;
  - дату можно **переопределить вручную** в поле «Факт завершения» модалки 6.10 (в т.ч. поставить другую дату после «Выполнено»);
  - при изменении статуса **с** «Выполнено» **на** другой — `doneDate` **очищается** (`null`);
  - `doneDate` не зависит от `pct`: может быть заполнена и при pct < 100 (например, закрытие с оговорками) — это допустимо и без предупреждения.
- **Расчёт досрочности** (для каждой задачи lvl≥2 с `doneDate ≠ null`):
  - `delta = effEnd − doneDate` (в днях текущего режима: календарные или рабочие, 6.19):
    - `delta > 0` — **выполнено досрочно на N дней** (N = delta);
    - `delta = 0` — **выполнено точно в срок**;
    - `delta < 0` — **просрочка N дней** (учёт «досрочно» не применяется; N = |delta|).
- **Отображение:**
  - **бар** (6.3): бейдж «✓ досрочно на N дн.» при `delta > 0`, «✓ точно в срок» при `delta = 0`; при `delta < 0` бейджа нет;
  - **тултип** (6.7): строка «Факт»: `дата · досрочно на N дн.` | `в срок` | `просрочка N дн.`;
  - **карточка** (6.4, п. 5): количество досрочно выполненных задач и среднее сдвигание;
  - **CSV-экспорт** (6.22): колонки «Факт завершения» и «Досрочно (дн.)».
- **Связь с планом:** досрочность **не** меняет даты плана (`start`/`end` не пересчитываются), не влияет на CPM (6.21) и зависимости (6.20) — это аналитическая метрика «план vs факт».
- **Пересчёт:** при любом изменении `doneDate`, `effEnd` (в т.ч. авто-окончания, 6.11), режима дней (6.19).
- **Экспорт/импорт:** JSON — поле `doneDate` (6.14/6.15, §7); валидация формата даты (ошибка — блокирует; позже `end` — предупреждение); CSV — 6.22.
- **Перенос WBS** (6.18.1): `doneDate` переносится вместе с записью на новый ID автоматически; **при переносе на lvl1 — обнуляется** (инвариант §3.1, §6.18.1).

### 6.28. Каталог исполнителей

- **Назначение:** справочник людей-исполнителей (ФИО + должность), из которого выбираются **Ответственный**, **Исполнитель** и **Соисполнитель** задач и направлений. План ссылается на исполнителей **жёстко по id** (3.4): в записях хранятся `ownerId`/`execId`/`coId`.
- **Хранение:** `oati_gantt_executors_v1` (см. §4, 3.4). Персистентно; пустой каталог — нормальное стартовое состояние.
- **Интерфейс — модалка** (отдельное «окно», не постоянный блок страницы):
  - открывается кнопкой **«Исполнители (N)»** в панели инструментов, где N = количество записей каталога;
  - содержимое:
    - **список** исполнителей (порядок — по id): ФИО · должность (если задана) · бейдж «в N задачах» (количество записей плана, где `ownerId`/`execId`/`coId` равны этому id; подсчёт по всем трём ролям) · кнопки «✎ Изменить» и «✕ Удалить»;
    - **форма добавления** сверху: **ФИО*** (input, до 80 символов) + **Должность** (input, до 80 символов, необязательная) + кнопка «Добавить»;
  - **данные не теряются** при закрытии модалки (формы чистятся, каталог нет).

- **Добавление:**
  - валидация (блокирующая): пустое ФИО (после trim); **дубликат ФИО** в каталоге (сравнение — trim + без учёта регистра);
  - при успехе — запись `{id: nextExecutorId(), name, role}` добавляется, `saveExecutors()`, список перерисовывается;
  - «в N задачах» у новой записи = 0 (пока не назначена).

- **Редактирование («✎»):**
  - переводит строку в режим правки (поля ФИО* + Должность, «Сохранить»/«Отмена»);
  - валидация та же, что при добавлении (дубликат проверяется **среди остальных**, исключая саму запись);
  - при смене ФИО — `confirm`: **«Имя используется в N задачах плана. Обновить имя во всех ссылках?»** — да (по умолчанию): сохранение нового имени; т.к. ссылка по id, **никакой дополнительной подмены в плане не требуется** — все задачи сразу отобразят новое имя; нет: сохранение отменяется.

- **Удаление («✕»):**
  - если исполнитель не назначен ни в одной задаче — `confirm` «Удалить исполнителя …?» → удаление;
  - если назначен (N > 0) — `confirm` с перечислением: «Исполнитель назначен в N задачах (ответственный/исполнитель/соисполнитель). После удаления в этих задачах будет показано «— (исполнитель не найден)». Удалить?» → при подтверждении запись удаляется **только из каталога**; ссылки в плане (`ownerId` и т.п.) остаются как сиротские (3.4, 6.7);
  - **отмена** — каталог не изменяется.

- **Комбобоксы в формах задач/направлений** (6.8, 6.10) — требование «выбор из списка»:
  - реализация — нативный **комбобокс**: `<input list="…">` + `<datalist>` (или эквивалентная ванильная реализация): выпадающий список всех исполнителей каталога **и возможность свободного ввода**;
  - **свободный ввод** допустим: введённое ФИО не найдено в каталоге → при сохранении **создаётся** запись каталога (id = `nextExecutorId()`) и назначается на поле; если введённое совпадает с существующим (trim, регистр не учитывается) — назначается существующий id, показывается **toast-уведомление** «Использован существующий исполнитель: <ФИО>» (см. ниже); **`[уточнено]`** при этом существующая запись каталога **не модифицируется** (имя и должность сохраняются как есть);
  - пункт **«＋ Новый исполнитель…»** (закреплён вверху списка): выбирается → рядом раскрывается инлайн-поле «ФИО нового исполнителя*» (+ «Должность»); при сохранении формы запись создаётся в каталоге и назначается; **при отмене формы в каталог ничего не пишется**;
  - пустой выбор (очистка поля) → `null` (исполнитель снимается);
  - поле «Должность» при инлайн-создании необязательное;
  - форма добавления (6.8) использует комбобокс для **Ответственного**; модалка редактирования (6.10) — для **Ответственного**, **Исполнителя** и **Соисполнителя** (поля `execId`/`coId` до появления каталога заполнялись только импортом — теперь редактируемы полностью).
  - **`[уточнено]` Форма предупреждения о дубликате:** «Использован существующий исполнитель: <ФИО>» показывается в виде **toast-уведомления после успешного сохранения формы** (не блокирует сохранение, не показывается посреди ввода). Если в форме несколько полей совпали с существующими — ФИО перечисляются через запятую в одном toast.

- **Отображение:**
  - **бар** (6.3): подпись ответственного справа от бара = `effOwner` (разрешённое имя); сиротская ссылка → подпись не выводится;
  - **тултип** (6.7): строка «Ответственный: ФИО» (+ исполнитель, + соисп.); при сиротской ссылке — «— (исполнитель не найден)»;
  - должность в диаграмме **не** выводится (только в модалке каталога).

- **Экспорт/импорт:**
  - JSON — верхнеуровневый блок `executors` (§7): при экспорте выгружается **весь** каталог (в т.ч. неиспользуемые записи); при импорте блок **заменяет** текущий каталог целиком (аналог `workdays`); при отсутствии блока — каталог **не меняется** (для обратной совместимости с файлами без каталога: сиротские id будут показаны как «не найден», строковые `owner`/`executor`/`coexecutor` в «старых» файлах нормализуются в id с авто-созданием записей каталога, 3.4);
  - валидация импорта `executors` (предупреждения, не блокируют): не-массив → каталог не меняется; запись не-объект → пропущена; пустое имя → пропущена; дубликаты имён → вторая и далее пропущены (с предупреждением); отсутствует `id` → вычисляется `nextExecutorId()` (с предупреждением).
  - CSV — строка после таблицы (аналог `# workdays`): `# executors ФИО (Должность); ФИО2 (Должность2); …`; при импорте строка восстанавливает каталог (заменяет); должность может отсутствовать (`ФИО;` или просто `ФИО`); `ФИО (Долж)` без скобок/пусто → `role = ""`. Ссылки задач в CSV — **имена** (разрешённые, как сейчас); при импорте CSV имена связываются с каталогом: имя найдено в импортированном/текущем каталоге → его id; не найдено → создаётся запись каталога (3.4).

- **Взаимодействие с «Новая диаграмма»** (6.23): каталог исполнителей **очищается** (`oati_gantt_executors_v1 = []`) вместе с планом — перечисляется в модалке последствий.

- **Производительность:** каталог — единицы–десятки записей; `resolvePerson` — поиск по массиву (или Map, пересобираемый при изменении каталога). Подсчёт «в N задачах» — O(записей плана × 3) при рендере модалки.

- **Перенос WBS** (6.18.1): ссылки `ownerId`/`execId`/`coId` не зависят от WBS-ID — переносятся как есть (см. 6.18.1).

### 6.29. Авто-статус направления и фильтрация плана `[Версия 3]`

#### 6.29.1. Авто-статус и процент направления

- **Хранение.** В записи направления (lvl1) `status`, `pct`, `doneDate` остаются `null` (инвариант §3.1). Расчётные `effStatus`/`effPct` вычисляются функцией `dirAggregate(dirId)` по `dirKids(dirId)` (все lvl2-задачи направления + их lvl3-подзадачи) при каждом рендере и **не записываются** в план, localStorage, JSON или CSV.
- **Правила расчётного статуса** (по всем подзадачам направления):
  1. подзадач нет → `null` (бар остаётся тёмным «dir»); по статусному фильтру такое направление не совпадает ни с одним статусом (видно при «Все» или при совпадении по ответственному);
  2. все подзадачи имеют `status === "Выполнено"` → «Выполнено»;
  3. иначе есть хотя бы одна «Заблокировано» → «Заблокировано»;
  4. иначе есть «В работе», «Выполнено» или `pct > 0` → «В работе»;
  5. иначе → «Запланировано».
- **Расчётный процент:** взвешенное среднее `Σ(pct_i × effDays_i) / Σ(effDays_i)` по всем подзадачам; подзадача со статусом «Выполнено» учитывается как 100% даже при `pct = null`. Если все подзадачи выполнены — ровно **100%**; иначе значение ограничивается сверху **99%** (`min(99, round(...))`), чтобы 100% означало только полную готовность.
- **Где используется:** бар направления (цвет, заливка, текст «Готово 100%» / «В работе N%» / …), тултип (6.7) и фильтр по статусу (6.29.2). **Не влияет** на сводные карточки (6.4 считает только lvl≥2), CPM, зависимости и экспорт.
- **Пересчёт** автоматический при любом изменении статуса/процента подзадач, их дат, добавлении/удалении/переносе и смене режима дней; отдельного сохранения не требуется.
- **Редактирование:** в модалке направления с подзадачами поля «Статус»/«Процент» скрыты (6.10), показывается заметка «Окончание, статус и процент направления рассчитываются автоматически по подзадачам» (6.11).
- **Экспорт:** JSON/CSV для lvl1 выгружают `status`/`percentComplete` как `null` (хранимые значения); при импорте они по-прежнему игнорируются (6.14, 6.15, 6.22).

#### 6.29.2. Фильтрация плана

- **Элементы управления (в закреплённой шапке, отдельно друг от друга):**
  - **«Статус»** (`select #filterStatus`): «Все», «Выполнено», «В работе», «Заблокировано», «Запланировано». Для lvl≥2 сравнивается `status`, для lvl1 — расчётный статус (6.29.1).
  - **«Ответственный»** (`select #filterOwner`): «Все», «— Не назначен» (`__none__`), исполнители каталога (ФИО — должность, по алфавиту), а также осиротевшие `ownerId`, присутствующие в плане («— не найден (id)»). Сравнивается **только `ownerId`** (не исполнитель/соисполнитель).
  - **«Сбросить»** — активна только при хотя бы одном активном фильтре; очищает оба фильтра.
- **Матчинг:** строка соответствует, если выполнены **все** активные фильтры (логическое И). `__none__` соответствует строкам с `ownerId = null`.
- **Видимость дерева:** показываются **совпавшие строки и все их предки** (для сохранения иерархии). Несовпавшие потомки скрываются. Предки, которые сами не совпали, получают класс `filter-ctx` и приглушаются (`opacity: .55`), чтобы отличать контекст от результатов.
- **Свёрнутость:** при активных фильтрах игнорируется — ветки раскрываются, чтобы совпадения были видны. Клик по `▼/▶` в это время показывает toast «При активных фильтрах ветки развёрнуты…» и не меняет сохранённое состояние. После сброса фильтров сохранённое `collapsed` снова применяется.
- **Нет совпадений:** если план непуст и видимых строк 0, выводится строка-подсказка «Нет строк, удовлетворяющих фильтрам. Измените или сбросьте фильтры в шапке».
- **Строка состояния:** при активных фильтрах добавляется `показано: X из Y` и состав фильтров (статус/ответственный).
- **Область действия:** фильтры меняют **только набор отображаемых строк**. Не меняются: ширина колонки списка, диапазон таймлайна, сводные карточки, CPM/резервы, зависимости, данные плана, `dir_order`, экспорт JSON/CSV. Сортировка и WBS-нумерация не зависят от фильтров. **PDF/печать** снимают текущий DOM, поэтому отражают активные фильтры (отфильтрованный вид).
- **Персистентность:** состояние фильтров **не хранится** в localStorage; сбрасывается при перезагрузке, успешном импорте и «Новой диаграмме». При изменении каталога опции ответственного обновляются; выбранный id сохраняется, если он ещё есть в каталоге или в плане (сирота), иначе сбрасывается в «Все».
- **Взаимодействие:** редактирование, удаление, добавление и перетаскивание работают как раньше. Новая или изменённая запись может не соответствовать активному фильтру и будет скрыта до его сброса; это не ошибка. При переносе WBS пересчёт ID не зависит от фильтров.
- **`[уточнено]`** Фильтры — это представление, а не изменение плана: они не пишутся в `oati_gantt_plan_v1` и не выгружаются.

### 6.30. Название диаграммы `[Версия 4]`

- **Хранение.** Название диаграммы — это `plan.meta.project` (строка, до 80 символов). Оно не является полем записей задач и не влияет на план, фильтры, карточки, CPM или даты. Если значение пустое/отсутствует (старые планы), используется fallback **«SMART OATI»**.
- **Отображение.** H1 страницы имеет вид `<название> — проектный план (диаграмма Ганта)`; `document.title` — `<название> — диаграмма Ганта`. Название **не дублируется** в строке периода (6.2). H1 кликабелен (`cursor: pointer`, title-подсказка).
- **Переименование.** Два входа: кнопка **«Название…»** в закреплённой шапке (рядом с «Новая диаграмма») и клик по H1. Открывается модалка:
  - поле **«Название *»** предзаполнено текущим названием, `maxlength=80`, текст выделен;
  - пустое значение (после trim) блокируется ошибкой «Укажите название диаграммы.»;
  - «Сохранить»/Enter записывают `plan.meta.project = <trim>` и `plan.meta.updatedAt`, вызывают `savePlan()`, закрывают модалку, обновляют H1/`document.title` и показывают toast;
  - «Отмена», Escape и клик по фону закрывают без изменений.
- **Создание новой диаграммы.** В модалке «Новая диаграмма» (6.23) есть поле **«Название новой диаграммы»**; при открытии в него подставляется `«Новая диаграмма»` и текст выделяется. Пустое значение при «Создать» заменяется на `«Новая диаграмма»`. Название сразу отображается в H1.
- **Загрузка/импорт.** При загрузке H1 строится из `plan.meta.project`. JSON-импорт использует непустое поле `project`; CSV-импорт — блок `# project` (6.22). Если в файле имени нет или оно пустое, **сохраняется текущее** название диаграммы; если и его нет — fallback «SMART OATI».
- **Экспорт.** JSON выгружает название в `project` (6.14); CSV — в блок `# project` после таблицы (6.22). PDF/печать показывают название в H1 (снимок DOM); имена файлов экспорта остаются фиксированными (`SMART_OATI_…`).
- **Персистентность.** Название хранится в `oati_gantt_plan_v1` (`meta.project`) и переживает перезагрузку. «Новая диаграмма» устанавливает новое имя (введённое или «Новая диаграмма»); импорт — по правилам выше.

### 6.31. Интерактивное редактирование связей `[Версия 7]`

#### 6.31.1. Режим «Связать» (добавление)

- Кнопка **«Связать»** в панели инструментов (рядом с чекбоксом «Стрелки зависимостей») включает/выключает режим. В режиме — активная подсветка кнопки, курсор `crosshair` над барами, подсказка-toast. Состояние режима — только текущий сеанс (не сохраняется).
- **Порядок:** первый клик по бару выбирает **предшественника** (строка получает класс `link-source`, бар — синий контур), второй клик по другому бару — **последующую** задачу, после чего связь добавляется в `deps` последующей, план сохраняется, режим выключается, диаграмма перерисовывается, показывается toast. Связь получает стиль по умолчанию.
- **Самосвязь** (тот же бар) — toast, связь не создаётся, режим остаётся активным. **Дубликат** (связь уже есть) — режим выключается и открывается редактор существующей связи (6.31.2). Если предшественник был удалён/больше не найден — toast и режим выключается.
- **Циклы** не блокируются: связь создаётся, граф и строка состояния показывают предупреждение (6.20).
- **Отмена:** повторный клик по «Связать» или `Escape` (если не открыта модалка). Клик по стрелке в режиме связи выключает режим и открывает редактор связи.
- **Ограничения режима:** перетаскивание баров, строк дерева и сдвиг дат стрелками клавиатуры отключены, чтобы клик не приводил к случайному изменению плана. Прочие элементы (фильтры, прокрутка, ресайз колонки, флаги/сворачивание/удаление) работают. Связывать можно только видимые бары (фильтры/свёрнутость учитываются).
- Импорт и «Новая диаграмма» выключают режим.

#### 6.31.2. Редактор связи (клик по стрелке)

- В SVG-оверлее для каждого ребра добавлена невидимая хит-линия (10 px, `pointer-events: stroke`), расположенная под барами. Клик по ней открывает модалку «Связь: A → B». Если стрелки скрыты чекбоксом (6.20), клик недоступен.
- **`[Версия 9]` Наведение** на хит-линию подсвечивает обе соединяемые строки и линию (6.20); при открытии/закрытии редактора и уходе курсора подсветка снимается.
- **Поля модалки:** предшественник (`select`, все записи плана, включая направления) и последующая (`select`), цвет (`input[type=color]`), стиль линии (`solid`/`dashed`/`dotted`), форма (`orthogonal`/`straight`/`curved`). Заголовок показывает выбранные концы.
- **Валидация (блокирующая):** оба конца выбраны; концы различны; id существуют в плане; при изменении концов новая связь не должна уже существовать (изменение только стиля у той же связи разрешено). Циклы разрешены и отмечаются графом.
- **Сохранение:** старая связь удаляется из `deps` прежней последующей (если есть), новая добавляется; стиль переносится с `oldFrom>oldTo` на `newFrom>newTo`; старый ключ стиля удаляется; `meta.depStyles` очищается от несуществующих рёбер; `savePlan()` и `renderAll()`.
- **Удаление:** кнопка «Удалить связь» (с `confirm`) удаляет ребро из `deps`, удаляет его стиль и перерисовывает граф.
- **Сброс стиля:** кнопка «Сбросить стиль» устанавливает контролы в значения по умолчанию; они применяются по «Сохранить», и запись стиля удаляется (умолчание не хранится).
- **Закрытие:** «Отмена», Escape и клик по фону закрывают без изменений.
- Поле «Зависимости» в модалке задачи (6.10) остаётся альтернативным способом редактирования `deps`; стиль новой связи, добавленной через это поле, — по умолчанию.

#### 6.31.3. Стиль связи

- **Хранение:** `plan.meta.depStyles` — объект `{ "from>to": { color, dash, shape } }` (4). Хранятся только **нестандартные** стили; отсутствие ключа = умолчание: `color="#94a3b8"`, `dash="solid"`, `shape="orthogonal"`.
- **Нормализация:** `color` — `#rrggbb` (иначе умолчание), `dash` ∈ `solid|dashed|dotted`, `shape` ∈ `orthogonal|straight|curved`. Неизвестные значения заменяются умолчаниями.
- **Отрисовка (приоритет):**
  - цвет: цикл/нарушение → `#dc2626`; иначе критическая связь → `#0f172a`; иначе пользовательский цвет (или `#94a3b8`). Наконечник маркера создаётся под фактический цвет.
  - толщина: критическая — 2.5 px, остальные — 1.5 px.
  - штрих: цикл — принудительно `4 3`; иначе пользовательский `dashed` ("6 4") / `dotted` ("2 3") / `solid` (нет).
  - форма: пользовательская (по умолчанию ортогональная).
- Стиль влияет **только на отображение**; CPM, резервы, зависимости и статусы не меняются.
- **Чистка и перенос:** при удалении связи/задачи, изменении `deps` и импорте записи стилей для несуществующих рёбер удаляются; при перенумерации WBS (6.18.1) ключи пересчитываются по `idMap`. При загрузке выполняется очистка orphan-стилей.
- **Экспорт/импорт:** JSON — верхнеуровневое поле `depStyles` (6.14, §7); CSV — блок `# depstyles` (6.22). При отсутствии поля/блока стили сбрасываются в `{}`; невалидные записи игнорируются; стили для несуществующих рёбер отбрасываются.

#### 6.31.4. Формат CSV-блока стилей

`# depstyles 1.1>1.2:#2563eb|dashed|curved; 1.2>1.3:#16a34a|dotted|orthogonal`

- После `# depstyles` — пары `from>to:color|dash|shape`, разделённые `; `; `|` внутри записи, чтобы не конфликтовать с разделителем CSV `;` и запятыми. Цвет — `#rrggbb`.
- Пустой блок или отсутствие строки → стили `{}`. Записи с неверным ключом/значениями пропускаются; стили для отсутствующих рёбер отбрасываются при применении.

- Наименования/даты/статусы/pct — текущие значения плана.
- **`[уточнено, Версия 4]` `project`** — название диаграммы (6.30); при импорте непустое значение становится именем, при отсутствии/пустом — сохраняется текущее название.
- **`[уточнено, Версия 3]`** `status` и `percentComplete` у направлений — всегда `null` (хранимые значения); расчётный авто-статус/процент (6.29) в экспорт не попадает и всегда пересчитывается из подзадач. `doneDate` у направлений также всегда `null`.
- `end` направления — рассчитанное (по подзадачам).
- `level` при импорте можно опустить — выводится из количества точек в `id` (с предупреждением).
- **`[уточнено]` `source`** — человекочитаемый источник плана: `"диаграмма собрана в браузере"` (ручное наполнение), `"новая диаграмма"` (после §6.23), **имя импортированного файла** (например, `SMART_OATI_диаграмма_Ганта_экспорт_2026-10-23.json` — после §6.15), `"импорт из JSON"` / `"импорт из CSV"` (fallback, если имя файла недоступно), либо произвольная человекочитаемая метка от внешнего инструмента/скрипта (без валидации). Полная таблица — §4.
- `description` (6.25) — описание записи; при отсутствии/null — описание отсутствует.
- `doneDate` (6.27) — фактическая дата завершения (`ГГГГ-ММ-ДД` или `null`); некорректный формат блокирует импорт, `doneDate` позже `end` — предупреждение; **у направлений (lvl1) всегда `null`** (§3.1).
- `comments` (6.26) — массив `{id, text, author, createdAt, updatedAt}`; не-массив → `null` с предупреждением; комментарии без `text` пропускаются с предупреждением; отсутствующие `id`/`createdAt` довычисляются при импорте.
- `executors` (6.28) — массив `{id, name, role}` (каталог исполнителей); выгружается целиком; при импорте **заменяет** текущий каталог; при отсутствии блока каталог не меняется. Валидация: не-массив / не-объект / пустое имя / дубликат имени → пропуск записи с предупреждением; отсутствующий `id` → `nextExecutorId()`.
- **`[уточнено, Версия 7]` `depStyles`** (6.31.3) — объект `{ "from>to": {color, dash, shape} }`; содержит только нестандартные стили. При импорте не-объект → `{}` с предупреждением; некорректные ключи/значения пропускаются/нормализуются; стили для отсутствующих рёбер отбрасываются; при отсутствии поля — `{}`.
- `ownerId` / `execId` / `coId` (3.4, 6.28) — **жёсткие ссылки** на `id` из `executors` (`null` — не назначен). Обратная совместимость: в записях «старого» формата поля `owner` / `executor` / `coexecutor` (строки с ФИО) при импорте нормализуются в `ownerId`/`execId`/`coId` — имя ищется в импортированном/текущем каталоге (trim, регистр не учитывается), при отсутствии создаётся новая запись каталога; строковые поля после нормализации отбрасываются. Ссылка на id, отсутствующий в каталоге, принимается как есть (отобразится «— (исполнитель не найден)»).
- `workdays` (6.19): `mode` — `calendar` | `workdays`; `holidays` — массив `{date: "ГГГГ-ММ-ДД", name: string}`. При импорте восстанавливается в `oati_gantt_workdays_v1`. **`[уточнено]`** При отсутствии блока — режим сбрасывается на `{mode: "calendar", holidays: []}` (см. §6.15, §6.19).
- `workdays` также выгружается в CSV-экспорт отдельным блоком после таблицы (см. 6.22).
- **`[уточнено, Версия 4]`** Название диаграммы (`project`) в CSV выгружается отдельным блоком `# project <название>` после таблицы (перед `# depstyles` и `# workdays`); при импорте блока нет или он пуст — сохраняется текущее название (6.30).
- **`[уточнено, Версия 7]`** Стили связей в CSV — блок `# depstyles from>to:color|dash|shape; …` (6.31.4); при отсутствии блока — `meta.depStyles = {}`.

## 9. Ненагруженные требования (non-functional)

1. **Один файл, нулевая сборка** — файл можно открыть двойным кликом.
2. **Изоляция данных** — данные только в localStorage браузера; разные браузеры/устройства не видят правки друг друга (только через экспорт/импорт).
3. **Производительность** — рендер типового плана (до ~100 строк) < 100 мс; `O(n²)` в `descStats` допустим. Граница 1000 строк — мягкий ориентир (без виртуализации, т.к. PDF-экспорт требует полного DOM): целевой порядок — < 1 с. Замеры (2026-10-23, headless Chrome, реальный layout): 29 строк ≈ 22 мс; 1000 строк ≈ 0,3 с. `[уточнено]`
4. **Устойчивость к мусору** — все чтения localStorage в `try/catch`; повреждённые данные → значения по умолчанию (пустой план).
5. **Деградация PDF** — без сети доступна системная печать.
6. **Безопасность** — никаких секретов в файле; валидация ввода; `esc()` при вставке пользовательских строк в HTML.

## 10. Проверка (приёмка)

Метод: скрипт (Node) извлекает `<script>` из HTML (`node --check` — синтаксис), затем исполняет его в DOM-песочнице **jsdom** (реальный HTML-документ, `localStorage` в памяти, стабы `URL.createObjectURL`/`confirm`/`print`) и проверяет сценарии. Обязательный набор:

1. **Первый запуск** — при пустом localStorage открывается пустой план: пустая таблица со шкалой и подсказкой, нулевая сводка, `nextTopId` = `1`.
2. **Шкала/диапазон** — min/max пересчитываются по датам; изменение конца задачи расширяет диапазон.
3. **Сводка** — % «по дням» = взвешенная сумма; карточки пересчитываются. **`[Версия 3]`** Карточки считаются по полному плану и **не зависят от фильтров**; авто-статус направления в карточки не входит.
4. **Сворачивание** — lvl1 скрывает lvl2/lvl3, lvl2 с подзадачами скрывает lvl3; бейдж «скрыто: N» (все потомки для lvl1, lvl3 для lvl2); кнопка только у строк с потомками; вложенные состояния независимы; персистентность; при фильтрах свёрнутость игнорируется, клик по кнопке — toast.
5. **Флаги БП/СП** — toggle, персистентность, чистка при удалении.
6. **Добавление** — в lvl2 и lvl3; новое направление (id = max+1); блокировки (название, даты, имя направления); мягкое предупреждение Jira; `pct=100` при «Выполнено»; **`[уточнено]`** `maxlength` полей: название 200, зависимости 120.
7. **Удаление** — каскад потомков; чистка flags/dir_order; удаление последней записи оставляет пустой план.
8. **Редактирование** — правки пишутся прямо в запись и сохраняются; валидации (pct, даты, название); отображение/тултип/экспорт используют новые значения; **`[уточнено]`** для lvl1 поля «Статус», «Процент», «Факт завершения» скрыты, а при сохранении принудительно обнуляются. **`[Версия 3]`** Для lvl1 отображение/тултип/фильтры используют расчётные статус/процент (6.29.1).
9. **Jira** — чип в строке, тултип, экспорт, импорт, очистка.
10. **Даты** — изменение дат задачи сдвигает бар; авто-окончание направления и задачи с подзадачами (max подзадач); disabled-поле в модалке; откат после удаления последней поздней подзадачи; строка без детей — ручное.
11. **Порядок направлений** — перенос по номеру, клампинг, дети следуют, новый — в конец, экспорт/импорт round-trip, очистка при удалении.
12. **Название** — переименование любой записи (in place); пустое заблокировано; дерево/тултип/экспорт используют новое.
13. **Экспорт/импорт** — схема полей; блокирующие ошибки vs предупреждения; применение заменяет план целиком; пустой `tasks` отклоняется. **`[Версия 3]`** У направлений `status`/`percentComplete` выгружаются как `null` (расчётный авто-статус не экспортируется); round-trip не даёт предупреждений по lvl1. **`[Версия 4]`** Название диаграммы переносится через JSON `project` и CSV `# project`; если имени в файле нет — сохраняется текущее (6.30).
14. **Drag & drop** — сдвиг бара меняет `start`/`end` с сохранением длительности; snap по дням (календарным/рабочим); ручки краёв меняют длительность; `Escape` отменяет; клик без сдвига открывает модалку; у направления с авто-окончанием перетаскивается только начало (**`[уточнено]`** правая ручка `.disabled`, при попытке — toast); клавиатурные сдвиги.
15. **Рабочие дни** — переключение режима пересчитывает `effDays`, сводку «по дням», snap и тултип; праздники исключаются из счёта; режим и праздники персистентны и выгружаются/восстанавливаются в JSON (`workdays`) и CSV. **Приведение дат:** при добавлении, редактировании, перетаскивании бара и клавиатурном сдвиге в режиме «Рабочие» даты автоматически не попадают на выходные/праздники (начало — вперёд, окончание — назад/вперёд по правилу 6.19, при сдвиге бара длительность в рабочих днях сохраняется); в режиме «Календарные» даты не меняются. **`[уточнено]`** При импорте без блока `workdays` режим сбрасывается на «Календарные».
16. **Зависимости** — стрелки finish→start рисуются по `deps`; нарушение срока подсвечивается красным + предупреждение в тултипе; цикл зависимостей обнаруживается (красные рёбра, предупреждение, CPM отключён); самоссылка и отсутствующий предшественник — предупреждения без рёбер. Редактирование: модалка (все уровни), экспорт/импорт (JSON `dependencies`, CSV «Зависимости»). **`[Версия 7]`** Добавление — режим «Связать»; клик по стрелке (хит-линия) открывает редактор связи с изменением концов и стиля (цвет/штрих/форма), удалением и сбросом стиля; стили переносятся в JSON `depStyles` и CSV `# depstyles` (6.31).
17. **Критический путь** — CPM (forward/backward pass) считает резервы; критические задачи подсвечены (контур + «КП» + утолщённые стрелки); карточка «критический путь: N дн.»; пересчёт при изменении дат/зависимостей/режима дней; при цикле — «—».
18. **CSV** — экспорт: UTF-8 BOM, `;`, фиксированные колонки, текущие значения; импорт: автоопределение разделителя, синонимы заголовков, доля-процента, булевы БП/СП (**`[уточнено]`** `1/0`, `да/нет`, `есть/нет`, `yes/no`, `true/false`), те же блокирующие/неблокирующие проверки; применение идентично JSON-импорту.
19. **Новая диаграмма** — модалка с пояснением и полем названия (6.30); полная очистка плана и состояния (флаги, **каталог исполнителей**, свёрнутые, порядок, режим дней); пустой план отображается пустой таблицей со шкалой и подсказкой; `nextTopId` = `1`; персистентность пустого плана; удаление последней задачи не сбрасывает настройки; **`[уточнено]`** `meta.source = "новая диаграмма"`. **`[Версия 3]`** Оба фильтра сбрасываются в «Все». **`[Версия 4]`** Введённое название (или «Новая диаграмма» при пустом) сохраняется в `meta.project`, отображается в H1 и `document.title`.
20. **Перенос задач (drag строки)** — перетаскивание наименования меняет порядок и вложенность; «внутрь» вкладывает, «перед/после» вставляет соседом; WBS перенумеровывается, `deps`/`flags`/`collapsed` переносятся на новые ID; запрет на дроп в себя/потомка и на переполнение глубины > 3; недопустимый дроп не меняет план; `Escape` отменяет перенос; клик без переноса выделяет строку; **`[уточнено]`** при переносе на lvl1 поля `status`/`pct`/`doneDate` обнуляются; при дропе «внутрь» свёрнутой строки (направления/задачи) — она разворачивается.
21. **Подзадача из строки (кнопка «＋»)** — кнопка есть у `lvl 1`/`lvl 2` и отсутствует у `lvl 3`; нажатие открывает модалку добавления с предвыбранным родителем (этой строкой); «＋» у направления создаёт `lvl 2`, у задачи — `lvl 3`; ID = `nextChildId(parent)` (следующий свободный в ветке); запись сохраняется в план, родительская строка (задача/направление) разворачивается, новая строка выделяется; добавление без выбранного родителя блокируется ошибкой; открытие модалки и сохранение **не сбивают прокрутку страницы**.
22. **Масштаб диаграммы** — кнопки «−/+» меняют масштаб (уровни 0.25…4, по умолчанию 1): меняется **пиксельная ширина таймлайна** (`pxPerDay × z`, ширина дорожки `--timeline-w`), диапазон дат остаётся полным; ширина колонки списка задач, шрифты и состав строк не меняются. **`[Версия 5]`** Колонка названий закреплена (`position: sticky; left: 0`) и не масштабируется; прокручивается только таймлайн. При z > 1 таймлайн шире видимой области → включается горизонтальная прокрутка; центр видимой области таймлайна (по дате) сохраняется при смене масштаба; уровень сохраняется; на крайних уровнях кнопки блокируются; при малом масштабе подписи недель скрываются.
23. **Диаграмма не накрывает список задач** — дорожка обрезает содержимое (`overflow: hidden`), а `left`/`width` баров ограничены `[0 %; 100 %]`: при зуме задачи за пределами видимого диапазона рисуются обрезанными по краю, названия задач в левой колонке не перекрываются; подпись ответственного не выходит за дорожку.
24. **Полосы прокрутки** — над диаграммой (`.top-scroll`, sticky под панелью инструментов) и под панелью (`.bottom-scroll`) есть две синхронные полосы; нативная полоса панели скрыта. Прокрутка любой из них двигает панель, панель синхронизирует обе; полосы появляются только при горизонтальном переполнении и скрыты при печати. **`[уточнено]`** Заголовочная строка закреплена (sticky) при горизонтальной прокрутке; при вертикальной прокрутке страницы она уезжает вместе с диаграммой (§6.1). **`[Версия 5]`** Колонка названий закреплена и при горизонтальной прокрутке не сдвигается; обе полосы начинаются после неё (`margin-left = labelW`), их внутренняя ширина = `scrollWidth − labelW` (обычно `timelineW`). Прокручивается только таймлайн.
25. **Описание** — поле `desc` в форме добавления (6.8) и в модалке редактирования (6.10) для всех уровней; редактируется многократно in place; тултип показывает «Описание» только если заполнено; экспорт/импорт JSON (`description`) и CSV («Описание») round-trip; пустое → `null`; при переносе WBS (6.18.1) переносится с записью; лимит 2000 символов.
26. **Комментарии** — кнопка «💬 N» в строке (видна только при N > 0) и в модалке редактирования открывает модалку комментариев; добавление (текст + автор, по умолчанию ответственный), редактирование (текст, `updatedAt` = сегодня, `createdAt` сохраняется), удаление (с `confirm`); список по возрастанию `createdAt`; пустой текст блокируется; при N = 0 кнопка исчезает, `comments = null`; тултип — «N» + текст последнего; переносится при перенумерации WBS; экспорт/импорт JSON (`comments`) и CSV («Комментарии») round-trip; **`[уточнено]`** счётчик N в строке обновляется при закрытии модалки комментариев.
27. **Досрочное выполнение** — поле `doneDate`: автозаполнение сегодняшней датой при переходе статуса в «Выполнено» (при добавлении и редактировании), ручная правка в поле «Факт завершения», очистка при смене статуса с «Выполнено»; у lvl1 поле скрыто; расчёт `delta = effEnd − doneDate` в днях текущего режима: > 0 — бейдж «✓ досрочно на N дн.» на баре + «Факт» в тултипе, = 0 — «✓ точно в срок», < 0 — без бейджа (в тултипе «просрочка N дн.»); карточка «досрочно: K задач · −N дн.» (среднее по досрочным); пересчёт при изменении дат/режима дней; даты плана, CPM и зависимости не затрагиваются; экспорт/импорт JSON (`doneDate`) и CSV («Факт завершения», «Досрочно (дн.)»); валидация формата (ошибка блокирует) и предупреждение при `doneDate > end`; **`[уточнено]`** при переносе записи на lvl1 `doneDate` обнуляется.
28. **Исполнители (каталог, 6.28)** — модалка по кнопке «Исполнители (N)»: пустой каталог на старте; добавление (ФИО* + Должность; блокировки: пустое имя, дубликат без учёта регистра); редактирование (дубликат проверяется среди остальных; ссылка по id — переименование сразу отражается во всех задачах, подтверждение при наличии ссылок); удаление (`confirm` с числом ссылок; записи плана не удаляются, id становится сиротским → «— (исполнитель не найден)» в тултипе, подпись на баре не выводится); подсчёт «в N задачах» по `ownerId`/`execId`/`coId`. Комбобоксы в форме добавления (Ответственный) и в модалке редактирования (Ответственный/Исполнитель/Соисполнитель): выбор из каталога + свободный ввод (не найдено → создаётся, совпало → существующий с предупреждением **`[уточнено]`** toast «Использован существующий исполнитель: <ФИО>» после сохранения; существующая запись каталога **не модифицируется**) + пункт «＋ Новый исполнитель…» (инлайн ФИО*+Должность; при сохранении формы — создание и назначение, при отмене — каталог не меняется); пустой выбор → `null`. **Миграция:** план/экспорт в «старом» формате (`owner`/`executor`/`coexecutor` строками) при загрузке и импорте нормализуется в id (имя ищется в каталоге, иначе создаётся запись); идемпотентно. Экспорт/импорт: JSON `executors` (заменяет каталог; без блока — не меняется) + id-ссылки; CSV — имена в колонках + строка `# executors ФИО (Долж); …` (заменяет); round-trip. «Новая диаграмма» очищает каталог.
29. **Компоновка модалки редактирования (6.10)** — ширина модалки 640 px; «Название задачи» и «Описание» — на всю ширину, остальные поля — в сетке 2 колонки (Ответственный | Исполнитель, Соисполнитель | Jira, Статус | Процент, Начало | Окончание, Факт завершения | Зависимости), кнопка «Комментарии» — на всю ширину; инлайн-строка «＋ Новый исполнитель…» раскрывается внутри ячейки сетки; **нет вертикальной прокрутки** при `scrollHeight ≤ clientHeight` на типовых окнах (≥ 768 px по высоте), в т.ч. при раскрытой инлайн-строке и видимых авто-заметках (6.11/6.27); проверка — измерение `scrollHeight`/`clientHeight` `.modal` после открытия (jsdom layout не считает — в браузерном/headless-запуске). **`[уточнено]`** для lvl1 поля «Статус», «Процент», «Факт завершения» скрыты — компоновка сетки для lvl1 сдвигается (соответствующие ячейки не занимают места).
30. **Авто-статус направления (6.29.1)** — все подзадачи выполнены → `effStatus = "Выполнено"`, `effPct = 100`, бар зелёный «Готово 100%»; не все выполнены → расчётный статус по правилам (блокировка/в работе/запланировано) и процент ≤ 99; направление без подзадач → `null` и тёмный бар; значения пересчитываются при изменении подзадач, не сохраняются и не выгружаются в JSON/CSV (там `null`); в карточки не входят.
31. **Фильтр по статусу (6.29.2)** — select в шапке; варианты «Все» + 4 статуса; направления фильтруются по расчётному статусу; показываются совпавшие строки и их предки, предки-контекст получают `filter-ctx`; свёрнутые ветки при фильтре раскрываются; при отсутствии совпадений — подсказка; сброс восстанавливает свёрнутость; строка состояния показывает `показано: X из Y`.
32. **Фильтр по ответственному (6.29.2)** — select в шапке; «Все», «— Не назначен», каталог (ФИО — должность), осиротевшие `ownerId` («— не найден (id)»); сравнение по `ownerId`; совмещение со статусным фильтром по логическому И; при удалении/переименовании исполнителя опции обновляются, выбранный id сохраняется, если он ещё в каталоге или плане.
33. **Фильтры в шапке и область действия (6.29.2)** — два отдельных select и кнопка «Сбросить» (активна только при фильтре); фильтры не меняются при простом рендере; сбрасываются при перезагрузке, импорте и «Новой диаграмме»; не влияют на ширину колонки, диапазон таймлайна, карточки, CPM, зависимости, `dir_order` и экспорт; в localStorage не пишутся; клик по `▼/▶` при активном фильтре показывает toast и не меняет `collapsed`.
34. **Название диаграммы (6.30)** — H1 и `document.title` строятся из `plan.meta.project` (fallback «SMART OATI»); кнопка «Название…» и клик по H1 открывают модалку; поле предзаполнено, `maxlength=80`, пустое имя блокируется; сохранение обновляет `meta.project`/`meta.updatedAt`, H1, `document.title` и localStorage; «Новая диаграмма» предлагает поле с дефолтом «Новая диаграмма» (пустое → «Новая диаграмма»); JSON `project` и CSV `# project` round-trip; отсутствие/пустое имя в файле сохраняет текущее название; строка периода название не дублирует.
35. **Ширина колонки названий (6.1)** — ручка `.label-resizer` в заголовке и строках; перетаскивание меняет ширину в диапазоне 360…(panel−240), сохраняет в `oati_gantt_label_w_v1` и пересчитывает `--label-w`/`--timeline-w`; Escape отменяет; двойной клик возвращает авто-ширину и удаляет ключ; при нехватке ширины наименование переносится (`white-space: normal`, `overflow-wrap: anywhere`), строка растёт по высоте, бар центрируется; авто-ширина не сбрасывается при импорте/новой диаграмме; зум не меняет ширину колонки.
36. **Связи на графе (6.31)** — кнопка «Связать» включает режим: первый клик по бару — предшественник (подсветка), второй — последующая; связь добавляется в `deps`, режим выключается; самосвязь блокируется, дубликат открывает редактор, Esc/повторный клик отменяют; перетаскивание баров/строк и сдвиг дат стрелками в режиме отключены; импорт/новая диаграмма выключают режим. Клик по стрелке (хит-линия 10 px под барами) открывает модалку: концы, цвет, стиль линии, форма, удалить/сбросить/сохранить; пустые/совпадающие концы и существующая новая связь блокируются; стиль переносится при смене концов; удаление удаляет `deps` и стиль. Стиль (`meta.depStyles`) влияет только на вид: цвет/штрих/форма, маркер перекрашивается; критические — тёмные/2.5 px, нарушения/циклы — красные, цикл — принудительный пунктир; JSON `depStyles` и CSV `# depstyles` round-trip; отсутствие сбрасывает `{}`; orphan-стили чистятся, при перенумерации WBS ключи пересчитываются.
37. **Задачи с подзадачами (6.5, 6.11)** — у lvl2 с lvl3 есть кнопка `▼/▶` (у lvl3 нет); сворачивание скрывает только lvl3, сама задача остаётся видимой с бейджем «скрыто: N»; состояние в `oati_gantt_collapsed_v1`, вложенные состояния независимы; при фильтрах свёрнутость игнорируется, клик по `▼/▶` показывает toast; `effEnd(lvl2)` = max окончаний lvl3 (через `descStats`), поле «Окончание» в модалке disabled, заметка про окончание задачи; статус/процент/факт остаются редактируемыми; правая ручка бара disabled, drag/клавиатура меняют только начало; если lvl3 нет — окончание ручное; удаление/перенумерация/новая диаграмма чистят `collapsed`.
38. **Наведение на связь (6.20)** — при наведении на хит-линию связи обе соединяемые строки получают `dep-hl` (голубой фон label + синий контур бара), линия — `dep-hover` (толще + тень); при `mouseout`, уходе курсора из диаграммы или открытии редактора подсветка снимается; работают связи любого уровня; при скрытых стрелках/скрытых строках подсветки нет; клик по хит-линии по-прежнему открывает редактор.

## 11. Глоссарий

| Термин | Значение |
|--------|----------|
| WBS | Work Breakdown Structure — иерархический ID: направление.задача.подзадача |
| Направление (lvl1) | Топ-уровень плана; хранимые `status`/`pct`/`doneDate` всегда `null`; отображаемые статус/процент — расчётные по подзадачам (6.29.1) |
| Задача с подзадачами | lvl2-задача с lvl3; сворачивает свои подзадачи, её эффективное окончание — max окончаний lvl3; статус/процент остаются собственными (6.5, 6.11) |
| Авто-окончание строки | `effEnd` для lvl1/lvl2 с потомками рассчитывается по самой поздней подзадаче; сохранённый `end` не меняется (6.11) |
| БП / СП | Флаги наличия документов (бизнес-план / спецификация) |
| Запись плана | Элемент плана (направление/задача/подзадача), редактируемый «на месте» |
| Отображаемое значение | Значение записи, используемое при отображении (для направления `end` рассчитывается по подзадачам; `effDays` зависит от режима дней) |
| Авто-статус направления | Расчётный статус lvl1 по подзадачам: все выполнены → «Выполнено»/100%, иначе агрегат «Заблокировано»/«В работе»/«Запланировано» (6.29.1) |
