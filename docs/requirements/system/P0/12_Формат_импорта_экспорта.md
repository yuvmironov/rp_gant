# P0: формат импорта и экспорта JSON/CSV
## SMART OATI

**Версия:** 1.0  
**Дата:** 2026-10-28

---

## 1. Артефакты

- `contracts/import-export/project-export.v2.schema.json`;
- JSON v2 — основной формат экспорта;
- JSON v9 — поддерживаемый legacy-формат импорта;
- CSV v2 — новый табличный формат;
- CSV v1 — поддерживаемый legacy-формат импорта.

Экспорт всегда формируется в **v2**.  
Импорт принимает v2 и legacy v9/v1.

## 2. JSON v2

### 2.1. Верхний уровень

```json
{
  "formatVersion": 2,
  "exportedAt": "2026-10-28T12:00:00Z",
  "projectId": "uuid",
  "diagramId": "uuid",
  "baseRevision": 42,
  "project": {},
  "diagram": {},
  "workdays": {},
  "executors": [],
  "directions": [],
  "tasks": [],
  "dependencies": [],
  "comments": []
}
```

Обязательны все перечисленные поля.

### 2.2. `project`

- `id`;
- `name`;
- `description`;
- `settings`.

### 2.3. `diagram`

- `id`;
- `name`;
- `description`;
- `dayMode`;
- `currentRevision`.

### 2.4. `workdays`

- `mode` — `calendar`/`working`;
- `holidays` — массив `{date, name}`.

### 2.5. `executors`

- `id`;
- `lastName`;
- `firstName`;
- `middleName`;
- `fullName`;
- `position`;
- `linkedUserId`.

### 2.6. `directions`

- `id`;
- `wbsCode`;
- `sortOrder`;
- `name`;
- `description`;
- `result`;
- `priority`;
- `startDate`;
- `endDate`;
- `jiraNumber`;
- `bpFlag`;
- `spFlag`;
- `assignments`.

### 2.7. `tasks`

- `id`;
- `directionId`;
- `parentTaskId`;
- `level` — 2/3;
- `wbsCode`;
- `sortOrder`;
- `name`;
- `description`;
- `result`;
- `status`;
- `progress`;
- `priority`;
- `startDate`;
- `endDate`;
- `actualEndDate`;
- `jiraNumber`;
- `bpFlag`;
- `spFlag`;
- `assignments`.

### 2.8. `assignments`

- `role` — `responsible/executor/co_executor`;
- `assigneeType` — `user/executor`;
- `assigneeId`;
- `displayName` — справочно.

### 2.9. `dependencies`

- `id`;
- `predecessorType`, `predecessorId`, `predecessorWbs`;
- `successorType`, `successorId`, `successorWbs`;
- `linkType`;
- `color`;
- `lineStyle`;
- `arrowShape`.

### 2.10. `comments`

- `id`;
- `entityType`;
- `entityId`;
- `authorUserId`;
- `authorDisplayName`;
- `body`;
- `mentionedUserIds`;
- `createdAt`;
- `updatedAt`.

### 2.11. Правила

- JSON — UTF-8 без BOM;
- даты — `YYYY-MM-DD`;
- дата-время — RFC 3339;
- UUID — строки;
- статусы/приоритеты — латинские коды;
- булевы — `true/false`;
- неизвестные поля v2 — предупреждение и игнорирование;
- неизвестная `formatVersion` — отказ;
- strict-схема — `additionalProperties: false`.

## 3. CSV v2

### 3.1. Параметры

- UTF-8 с BOM;
- разделитель `;`;
- первая строка — заголовки;
- одна строка — направление или задача;
- даты — `DD.MM.YYYY`;
- статусы — русские подписи;
- булевы — `Да/Нет`;
- прогресс — 0–100.

### 3.2. Колонки

```text
WBS;LEVEL;TYPE;ID;DIRECTION_ID;PARENT_ID;NAME;DESCRIPTION;RESULT;
RESPONSIBLE_TYPE;RESPONSIBLE_ID;RESPONSIBLE_NAME;
EXECUTOR_TYPE;EXECUTOR_ID;EXECUTOR_NAME;
COEXECUTOR1_TYPE;COEXECUTOR1_ID;COEXECUTOR1_NAME;
COEXECUTOR2_TYPE;COEXECUTOR2_ID;COEXECUTOR2_NAME;
START;END;ACTUAL_END;STATUS;PROGRESS;PRIORITY;JIRA;BP;SP;DEPENDENCIES
```

### 3.3. Мета-блоки

Перед таблицей:

```text
# formatVersion 2
# project <name>
# projectId <uuid>
# diagram <name>
# diagramId <uuid>
# exportedAt <iso>
# baseRevision <number>
# workdays <calendar|working>
# holidays <date>:<name>; <date>:<name>
# executors <id>|<lastName>|<firstName>|<middleName>|<fullName>|<position>|<linkedUserId>
# depstyles <fromWbs>><toWbs>|<color>|<lineStyle>|<arrowShape>
# comments <commentId>|<entityType>|<entityId>|<authorUserId>|<authorName>|<createdAt>|<body>|<mentionedIds>
```

### 3.4. Правила

- `TYPE` — `Направление`, `Задача`, `Подзадача`;
- у направления `DIRECTION_ID` пустой; `ID` — ID направления;
- у задачи `DIRECTION_ID` заполнен; `PARENT_ID` — для подзадачи;
- `RESPONSIBLE_*` — у направления и задачи;
- `EXECUTOR_*` — только у задачи;
- `COEXECUTOR1/2` — до двух;
- `DEPENDENCIES` — WBS-пары `fromWbs>toWbs`, разделитель `; `;
- комментарии и стили — в мета-блоках;
- пустые ячейки допустимы.

## 4. Legacy v9 JSON

Поддерживается импорт:

- `project`;
- `source`;
- `exportedAt`;
- `today`;
- `count`;
- `directionOrder`;
- `workdays`;
- `executors`;
- `depStyles`;
- `tasks`.

Маппинг:

| v9 | v2 |
|----|----|
| `level: 1` | `directions` |
| `level: 2/3` | `tasks` |
| `task` | `name` |
| `description` | `description` |
| `ownerId` | `assignments.responsible` |
| `execId` | `assignments.executor` |
| `coId` | `assignments.co_executor` |
| `deps` | `dependencies` |
| `priority` | `priority` |
| `hasBP`/`hasSP` | `bpFlag`/`spFlag` |
| `doneDate` | `actualEndDate` |
| `executors` | `executors` |
| `depStyles` | стили зависимостей |
| `workdays` | `workdays` |

ID legacy не являются UUID. При импорте создаются новые UUID; WBS/имена используются как fallback.

---

## 5. Legacy CSV

Импорт принимает старый CSV:

- 24 колонки;
- `# project`, `# depstyles`, `# workdays`, `# executors`;
- русские статусы;
- `Да/Нет`;
- `DD.MM.YYYY`.

Старый CSV конвертируется в v2.

---

## 6. Импорт

- асинхронный;
- `multipart/form-data`;
- 50 МБ;
- `202` + `jobId`;
- v2 — strict;
- v9/v1 — конвертер;
- неизвестная версия — `failed`;
- UUID сначала, WBS/имя — fallback;
- неизвестные исполнители не создаются;
- задачи без назначений попадают в отчёт;
- неизвестные упоминания игнорируются с предупреждением;
- ошибка не меняет диаграмму;
- payload удаляется после обработки.

---

## 7. Экспорт

- JSON v2;
- CSV v2;
- JSON — полный backup;
- CSV — Excel;
- UUID + WBS/имена;
- комментарии, упоминания, стили, праздники;
- файл до 50 МБ;
- синхронный.

---

## 8. Round-trip

Обязательное требование:

- экспорт → импорт → экспорт сохраняет семантически эквивалентный план;
- UUID могут быть пересозданы при импорте legacy;
- WBS и порядок могут нормализоваться;
- назначения, зависимости, комментарии, стили, праздники и флаги сохраняются.

---

## 9. Критерии приемки

1. JSON v2 соответствует схеме.
2. CSV v2 содержит все колонки.
3. Legacy JSON v9 импортируется.
4. Legacy CSV импортируется.
5. Неизвестная версия отклоняется.
6. Неизвестные поля v2 дают предупреждение.
7. UUID имеет приоритет.
8. WBS/имя используются как fallback.
9. Неизвестные исполнители не создаются.
10. Неизвестные упоминания игнорируются с предупреждением.
11. Комментарии/стили/праздники сохраняются.
12. Round-trip проходит.
13. Ошибка импорта не меняет план.
14. Payload удаляется.
15. Лимит 50 МБ.
