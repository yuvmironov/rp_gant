# Исполнители: проектная доступность и миграция назначений

Запись каталога исполнителей создаётся и редактируется только с непустым списком `projectIds`. Gateway проверяет, что все выбранные проекты активны; User Service хранит связи отдельно от членства и ролей пользователей. Каталог можно отфильтровать через `GET /api/v1/executors?projectId=<uuid>`.

Для ролей «исполнитель» и «соисполнитель» Gantt показывает и сервер принимает только пользователей с активной учётной записью и активным членством в текущем проекте. Изменение списка проектов каталога не добавляет и не отзывает пользовательские права. Существующие назначения справочной записи, которые нельзя преобразовать, остаются legacy и доступны для явной замены или удаления.

## Backfill старых назначений

Утилита `tools/backfill-executor-assignments.mjs` проверяет старые записи `assignee_type = 'executor'` по `linked_user_id` и текущему активному членству пользователя в проекте. Только подтверждённые записи преобразуются в назначения `user`; остальные остаются без изменений. Операция идемпотентна и пропускает уникальные конфликты.

Сначала запустите dry-run, передав процессу переменные подключения проекта (`DATABASE_URL` или `DATABASE_URL_PROJECT`) и адрес User Service (`USER_SERVICE_GRPC`):

```powershell
node tools/backfill-executor-assignments.mjs
```

Проверьте `convertibleAssignments` и `unresolvedLegacyAssignments`, затем явно запустите запись:

```powershell
node tools/backfill-executor-assignments.mjs --apply
```

Скрипт не загружает `.env.local` и не запускается автоматически. Выполнять его следует отдельно в выбранной среде, только после резервного копирования соответствующей project DB.
