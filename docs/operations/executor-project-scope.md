# Назначения по участникам проекта

Каталог исполнителей администрируется отдельно и не выдаёт доступ к проекту. Назначения задачами и подзадачами (`executor`, до двух `co_executor`) создаются только для активных пользователей — участников текущего проекта. Новые назначения из записей каталога запрещены. Оставшиеся в данных каталожные task-назначения являются legacy: интерфейс показывает их, чтобы назначение можно было явно заменить или удалить.

У направления единственное назначение — `responsible`, и оно может ссылаться только на активного пользователя — участника текущего проекта. Записи каталога исполнителей для ответственного направления не принимаются.

## Безопасный backfill перед миграцией схемы

`tools/backfill-executor-assignments.mjs` сначала выполняется в режиме dry-run и строит подробный отчёт по каждому назначению:

- активный task `responsible/user` перемещается в `executor/user`, если исполнитель ещё не назначен;
- если у задачи уже есть исполнитель, он сохраняется, а конфликтующий `responsible` удаляется с записью в отчёте;
- task `responsible/executor` перемещается в legacy `executor/executor` для ручной замены;
- неактивные task user-назначения и неактивные/неразрешимые ответственные направлений удаляются с объяснением в отчёте;
- каталоговый ответственный направления преобразуется в `responsible/user`, только если его `linked_user_id` — активный участник проекта; иначе запись удаляется с отчётом.

Утилита идемпотентна. Она не загружает `.env.local`, не запускается автоматически и изменяет только project DB, указанную переменными процесса (`DATABASE_URL` или `DATABASE_URL_PROJECT`); адрес User Service задаётся через `USER_SERVICE_GRPC`.

Сначала создайте резервную копию соответствующей базы и проверьте план без записи:

```powershell
pnpm backfill:task-assignments -- --dry-run --report task-assignments-dry-run.json
```

Проверьте поля `changes` и `unresolved` в отчёте. Только после согласования отчёта примените план:

```powershell
pnpm backfill:task-assignments -- --apply --report task-assignments-applied.json
```

После успешного backfill примените миграции project DB, включая `0008_assignment_roles_by_entity.sql`. Не запускайте миграцию ограничения до backfill: PostgreSQL намеренно отклонит её, если остаются недопустимые назначения.
